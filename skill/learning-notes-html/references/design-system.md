# 设计系统 · 笔记基准线(最终版)

单一强调色 + 灰阶的极简系统,反向抽取自一个教程 skill(sdd)的排版纪律,再经十几轮实战打磨定稿。
这份是**干净的最终真相**——直接照做。成品 CSS 已在 `assets/template.html`,新章节从模板起、别重造样式。

**一句话总纲:靠「结构」分级(字号 / 留白 / 顶边线 / 悬挂竖线 / 等宽小标签),不靠「颜色」分级。**
每想加一种颜色前,先问能不能用线 / 字号 / 小标签解决。

---

## 1. 字号只有 6 级

全站只允许这 6 个字号,写死成变量,任何元素只能取其一,不许再冒别的数字。这是「乱」的头号根因——第一版曾滚出 19 种字号。

| 变量 | 值 | 用途 |
|---|---|---|
| `--fs-micro` | 11px | 等宽小标签 / 图注 / 目录 / 面包屑 |
| `--fs-small` | 13px | 表格 / 代码 / 次要说明 |
| `--fs-body` | 15px | 正文 |
| `--fs-lead` | 16px | 一句话定义 / 导语 / h2 节号 |
| `--fs-h3` | **20px** | 子标题 |
| `--fs-h2` | **25px** | 小节标题 |
| `--fs-h1` | **34px** | 章标题(全页仅一个) |

> **2026-08-30 更正(本节原值与 §8 冲突)**:标题档以 §8「标题要够突出」为准 = **34/25/20**。
> 本节表格与下文的 18/22/30 是 2026-08-13 的旧值,§8 增补时漏改了这里,导致文档自相矛盾。
> 全站 63 页中 62 页早已是 34/25/20,样章 `02-Python基础.html` 是唯一漏网的,现已补齐。

三条铁律:
1. **行内代码固定 `13px`,绝不用 `em`**——em 会层层相乘出 11.31、12.18 这种怪数。
2. **绝不在正文写 `style="font-size:…"`**——散落的内联样式是「字号过多」第二大来源,一切样式进 CSS 类。
3. **图(SVG)里没写字体的 `<text>` 会回落 Arial**——已在模板加了 `figure svg text{font-family:var(--sans)}` 兜底,别删。

自检:浏览器里数一遍正文字号,应 = 7 种(11/13/15/16/**20/25/34**);字体 = 2 种(Noto Sans SC + JetBrains Mono),不该出现 Arial。

## 2. 配色:一个强调色 + 灰阶

| 变量 | 值 | 用途 |
|---|---|---|
| `--bg` | `#eef1f6` | 页面底(冷灰蓝纸) |
| `--surface` | `#ffffff` | 卡片 / 代码 / 图 的底 |
| `--ink` | `#14181f` | 正文墨色 |
| `--ink-soft` | `#55617a` | 次要文字 |
| `--ink-faint` | `#8b95a8` | 更淡(小标签、图里的说明) |
| `--rule` | `#d8dee9` | 分隔线 / 描边 |
| `--acc` | `#2743c7` 群青蓝 | **唯一强调色** |

**整页只有这一个彩色。** 其余全走墨黑 / 三级灰。强调蓝只用在:正文链接、真正的警示、按钮、目录/面包屑当前项、图里点一个重点节点。
**代码高亮也不上蓝/绿两色**——只用「墨 + 一档灰」:关键词加粗墨、注释淡灰斜体、字符串与输出走 ink-soft(详见 production-pipeline.md 的 Shiki 变体 A)。
行内代码底色 `#dbe2ef`(和页面底 `#eef1f6` 拉开,看得出;文字走 ink-soft,不刺眼)——别用和页面太近的灰。

## 3. 字体两套

- 正文:`Noto Sans SC / 微软雅黑 / 系统无衬线`(不挂 CDN,离线回落系统中文字体)。
- 等宽:`JetBrains Mono / Cascadia Code / Consolas`。**所有小标签、序号、代码、图里的编号**都用等宽。

## 4. 一条左边线:所有正文文字左边缘对齐(章法的命根)

页面显得「乱、没章法」的真正原因是**左边缘参差**:段落在 x=0、定义缩进 14px、说明框缩进 21px、还有人往最左塞个 `↓`——五种左起点像锯齿。

**铁律:段落、一句话定义、说明块、过渡句的文字左边缘,一律对齐到同一条线(x=0)。**
做法 = **悬挂竖线**:说明块用 `margin-left:-18px; padding-left:15px; border-left:3px`,竖线挂到版心外的沟槽里,文字回到 0、与段落齐。**去掉说明块的填充底色**(底色逼文字缩进、还漏进沟槽),块之间靠「竖线颜色 + 小标签」区分。
**不要在正文里塞方向符号**(`↓ →`),它们顶破左边线。
**列表也归这条线**:`ul/ol` 去默认缩进和小圆点,标记(`—` 或等宽序号)用 `li::before{position:absolute;left:-18~-24px}` 悬挂到沟槽,不用 `•`。
例外只有两个、且是刻意的:列表项标记、h2 的等宽节号——它们是「标记」不是「正文」,可带自己的缩进。

## 5. 层级四级 + 说明块共用一个骨架

层级:
| 级 | 处理 |
|---|---|
| h1 章标题 | 34px 粗,章首区,下一条 `--rule` 线,全页仅一个 |
| h2 小节 | 25px 粗 + **等宽节号(墨色、加粗、`--fs-lead`,和标题读成一体)** + **顶部一条 `--rule` 线** |
| h3 子标题 | 20px 粗,无线 |
| 一句话定义 `.one-liner` | 16px + 左侧 `--ink-faint` 悬挂竖线,每个概念开头那句 |

**不准**:给标题上底色 / 彩色 / 下划线;同一页出现两种 h2 样式;h2 节号做成很淡的小灰字(会和标题脱节)。

**框只有 3 类,不许造第 4 类:**
1. **悬挂左线说明块**——`.rationale / .callout / .callout.go / .callout.warn / .predict / .challenge` **共用同一段 CSS**(悬挂 3px 竖线 + 小标签 + 正文,无底色)。种类之间**只差左线颜色**:中性 = `--ink-faint`,真正的警示 = `--acc`。别的一律相同。
2. **带边框的白底卡**——代码块 / 图 `figure` / 单步演示 `.sim`:1px 描边 + 6px 圆角 + 白底,可选顶部标题条。图一定属于这类(每张 figure 套框,散内容被框收住、不再飘)。
3. **纯细线表格** `.tbl`——表头下一条墨线、行间 `--rule` 细线,不填色、不加外框;题注在**下方居中、灰**。

内容块小标签统一成一个安静 token(sans、13px、不大写、不上色、灰);过渡句 `.handoff` 就用朴素灰色段落(字号同正文、不加粗、不用斜体、无符号——中文斜体是合成假斜、发丑)。
**加粗要省**:过渡句一律不加粗;正文每段最多一处加粗领句,别让一句话里三四个词全黑。
去下划线:链接只留一条极淡下划线(hover 才变实);强调用加粗或悬挂竖线,不用下划线;标题 / 术语 / 表头绝不下划线。

## 6. 图的统一画法

一个概念一张图。图分四类,按本质选载体(详见 production-pipeline.md):
- **流程 / 关系图**(判断、循环、输入→处理→输出)→ **Mermaid** 预渲染静态 SVG。
- **辐射 / 环绕图**(中心目标 + N 块环绕)、**概念示意图**(贴标签盒子这种隐喻)→ **自制 SVG**,复用工具类 `.d-ink/.d-soft/.nf/.nf-acc/.nl/.nl-acc/.el` 保持和 Mermaid 一致的墨线白底 + 强调中心。Mermaid 只会画层级树,硬做辐射会挤成扇形。
- **本质是文本的**(报错 traceback)→ 做成 `.trace` 文本面板,不画图。
- **本质是表的**(列表索引格子)→ 做成 `.idxgrid` 表格,不画图。

自制 SVG 的关键技巧——**白描边光晕**:连线旁的文字加 `paint-order:stroke; stroke:var(--surface); stroke-width:4px`,文字被一圈底色包住,永远不和线、不和别的字打架。`viewBox` 上下各留 ~20px 防裁切;SVG 里 `font-family` 写**具体字体名**(`var()` 在 SVG 呈现属性里不生效)。**不要深色黑块**——重点节点用浅底 `#f4f6fb` + 蓝框。

## 6.5 收尾细节(2026-08-14 建 03 时补的一批)

- **标题要够突出**:h1/h2/h3 = 34/25/20px(比早期的 30/22/18 各大一档),和 15px 正文明显拉开,一眼看出是标题。
- **h2 节号贴着标题**:`.no` 用 `font-size:.9em`(相对 h2),跟着标题走、只比标题小一点,「7」和「ndarray」读成一体,别做成很淡的小灰字。
- **骨架清单别被通用行距撑开**:`.schema-panel li` 必须写 `margin:0`——否则通用规则 `article li{margin:.9em}` 会漏进来,骨架五项之间凭空多 13px,显得松垮。
- **块标签一律灰,连警示也是**:所有 `.label`(骨架/说明/警示…)统一 `--ink-faint` 灰,**别给 warn 标签上蓝**;警示的区分交给左线颜色。标签一旦有灰有蓝,就又变成「多种文字样式」。
- **行距按逻辑分层**:**一个分点「内」的换行收紧**(list li `line-height:1.55`)、**分点「之间」放开**(li `margin:.85em`);让每条 li 读成一个单元。而**紧凑清单**(骨架那种单行短项)要更紧(`margin:0; padding:3px`)。一句话:同一单元内小行距、不同单元间大间距。
- **自查区不自带重墨线**:`.self-check` 去掉 `border-top`,分节统一靠 h2 的顶边线;对应的 h2 **别加 `.bare`**,否则该节和上一节之间就没有分割线了。

## 6.6 文风:别露 AI 腔,加粗要省(同日补)

- **recap / 正文里不许出现「AI 自述」式的话**:如「角色仍是带路人——用图讲清 X,再把精读交给官方」。这是把 skill 的内部框架说给读者听,是套路味。recap 只讲实质:从上一章接来什么、本章把它变成什么、为什么重要。
- **加粗只用两处**:①专业术语**首次**出现时标一下;②真正的关键重点,辅助扫读。**同一个词后面每次都加粗 = 过度**,删掉。一句话里别三四个词全黑、别整句加粗。
- **少比喻**:一个概念给一个白话对照就够(如「数组=一整块对齐的内存」),别连续打比方、别给比喻再加引号强调。

## 7. 页面骨架(每篇一致,已在模板里)

1. 顶部**进度条** + **常驻面包屑**(课程首页 — 上一章 — 本章 — 下一章,当前项蓝色)。
2. 两栏:左正文(读栏 ≤ 820px)+ 右**常驻目录**(按大模块分组,滚动高亮当前节;窄屏自动隐藏)。目录 `a` 的 `data-toc-target` 必须等于对应 h2 的 `id`。
3. 章首:小标签 + h1 + 一段 recap(交代从哪来、到哪去)。
4. 章首骨架清单 `.schema-panel`(本章会立起来的地基)。
5. 正文按小节铺开;概念节之间用 `.handoff` 过渡句串成一条线。
6. 章尾:上一章 / 下一章两张导航卡。
