# 索引页 / MOC(整册落地页)的结构

一套学习库不只有章节页,还有一张**总入口 = MOC(Map of Content)**。它是复用框架的一部分——这套结构调过很多次,定型如下。新开一个库时照这个搭;它和章节页共用同一套设计系统(`design-system.md`)和 `assets/template.html` 里的 `:root` token,**同样单一强调色、自足单文件、离线**。

## 固定骨架(从上到下)

1. **Hero** —— 小标签行(`chip`,别用多色;统一走强调色或灰)+ h1 库名 + 一段 lede(这个库是什么、为谁做、路线几阶段)。
2. **「现在该做什么」指针块** —— 一个显眼的说明块,直接给出**当前该走的下一步**(读哪章 → 做哪个实验 → 做哪套题)。学习库最容易变成"囤了没人读的浅课",这块用来止囤、给唯一入口。
3. **阶段分区(Stage bands)** —— 每个阶段一条 `stage-band` 标题 + 一张 `card`,card 里一段目标说明 + 一个**课程清单** `course-list`。本库三阶段:基础课程 / 深度课程 / 项目。
4. **配套区(Support)** —— 三栏卡:实验室 / 题库 / 资料。
5. **本机环境档案** —— 一张表(工具 / 版本 / 说明),注明"仅描述当前这台电脑,换机重新核对"。是**可移植笔记**的一部分。
6. **页脚** —— 库名 + README(维护说明)链接。

## 课程清单条目(course-list li)的固定字段

每条 = **编号 + 标题(可学的带链接、未开的纯文字)+ 一句描述 + 状态徽标**。
状态词汇统一三档:`✓ 可学`(已开放)/ `规划中`(未做)/ 进行中。未开放的条目 `locked`(灰、不可点)。
编号体系:基础课程用 `01–08`,深度课程用 `D01–D11`,项目用 `P1–P6`——**编号前缀标明它属于哪个阶段**,一眼知道身处何处。

## 维护约定(MOC 是活的)

- 每做完一章,回 MOC 把该条从「规划中」翻成「✓ 可学」、补上链接,并更新「现在该做什么」指到新的下一步。
- 面包屑和章尾导航里的"下一章(制作中)"要和 MOC 状态一致。
- MOC 记录**顺序关系**(先读什么后读什么、哪个项目学完哪章才能做)——它替代文件夹,是整库的导航中枢。

## 收敛到基准线(现存 index.html 待办)

早期 index.html 还挂外部 `course.css`、有内联 `font-size`、用了 teal/gray 多色 chip——都违反基准线。改造时:去外部 CSS、并进 `:root` 单一强调色、内联字号进 6 级阶梯、chip 只用强调色或灰。结构不变,只换皮。
