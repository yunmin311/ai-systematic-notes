训练的本质:损失与梯度下降

上一章说模型能「从数据里学」,但一直没讲怎么学。这一章钻进这个黑箱:模型先用一个数(损失)量出自己错得多离谱,再顺着「下坡」方向一小步一小步地调,把这个数降到最低——这套调法叫梯度下降。搞懂它,「训练」就从黑话变成一个我能画出来的过程。

图解骨架约 40 分钟,外部精读 + 动手约 3~5 小时。全程只用到「差多少」和「坡度往哪」这种直觉,不推公式。每出现一个新词,当场用白话解释。

读完这一章,我脑子里会立起来的骨架

  • 损失函数——用一个数量出「预测和答案差多少」,越小越好
  • 梯度下降——顺着坡往下走,一步步把损失降到最低(下山)
  • 学习率——每一步迈多大;太大跳过谷底,太小走到天黑
  • 迭代与 epoch——反复走很多步,看完一遍数据算一个 epoch
  • 训练循环——预测 → 算损失 → 算坡度 → 调参数 → 重复
从哪来 · 到哪去

接上一章:第 5 章讲了「学好了」长什么样(泛化)。通向下一章:第 7 章 神经网络里,成千上万个参数就是靠本章的梯度下降来调的——反向传播只是「高效地算出每个参数的坡度」。本章是理解神经网络怎么学的地基。

4一句话本质

训练 = 不停地问两件事:「现在错多少?」(损失)和「往哪个方向调、能让错变少?」(梯度),然后朝那个方向挪一小步,反复千万次,直到错到最小。

模型内部有一堆可调的旋钮(参数)。一开始随便设,预测得很烂。训练就是:量出现在错多少,算出每个旋钮该往哪拧一点点能让错变小,拧一小步,再来一遍。像蒙着眼下山,靠脚感觉哪边是下坡,就往哪边挪一小步,一步步走到谷底。谷底就是「错到最小」——模型就调好了。

先把第一块立起来:模型怎么知道自己错了、错多少。

7损失函数:错多少

损失函数loss function:把「模型的预测」和「真实答案」之间的差距,压成一个数。这个数越小,模型越准;训练的目标就是把它降到最低。

没有这个数,模型就不知道自己好坏,更谈不上改进。最常见的做法:每个样本算「预测减答案」的差,平方后全部加起来求平均——这叫均方误差(MSE)。平方是为了让正负差都变成正的、且错得越离谱惩罚越重。分类问题用另一种(交叉熵),但思想一样:用一个数量出错得多远。

有了「错多少」这个数,下一步是最关键的:怎么调参数让它变小。

8梯度下降:顺坡下山

梯度下降gradient descent:把损失想成一片山地,当前参数是我站的位置。每一步感觉哪边是下坡(梯度),就往那边挪一小步,反复走,直到谷底(损失最小)。

「梯度」就是坡度——它同时告诉我「最陡的下坡朝哪」和「有多陡」。站在半山腰,我不用看到整座山,只要摸清脚下的坡,朝下坡挪一步,就离谷底更近一点。挪一步、重新算坡、再挪一步……千万次之后,基本停在谷底。这就是几乎所有 AI 模型「学」的底层动作,神经网络也不例外。

可能停在小坑里

真实损失曲面坑坑洼洼,梯度下降可能停在一个不是最深的小坑(局部最小)。实践里靠随机起点、动量等技巧缓解;对神经网络,这通常不致命,能到一个「够好」的坑就行。

每一步挪多大,是个要命的旋钮——学习率。

9学习率:每步迈多大

学习率learning rate:每一步往下挪的步长。太小,走到天黑还没到谷底;太大,一步跨过谷底、来回乱蹦甚至越走越高。

这是训练里最需要调的旋钮之一。步子太小,训练慢得让人抓狂;步子太大,直接跨过最低点,在两边反复横跳,损失降不下去反而炸掉。合适的学习率让损失又快又稳地下降。怎么找?看损失曲线:随训练平滑往下走就对了,一直不降或忽上忽下就是学习率不对。

走一步叫一次迭代,反复走很多步、看很多遍数据,这就引出迭代和 epoch。

10迭代与 epoch

一次迭代(iteration)=挪一步(用一批数据更新一次参数)。一个 epoch=把训练数据完整看过一遍。训练通常要很多个 epoch。

数据太多,不会一次全塞进去算,而是切成小批(batch),每批算一次损失、挪一步——这是一次迭代。所有批都过完一遍,算一个 epoch。为什么要很多 epoch:一遍下山远不够,得反复走很多趟才逼近谷底。判断该停没停,还是看损失曲线:降不动了、或验证集开始变差(过拟合),就该停。

把这五块串起来,就是所有训练代码共有的那个循环。

11训练循环:五步一圈

训练循环:预测 → 算损失 → 算梯度 → 更新参数 → 回到预测,一圈又一圈,直到损失够小或不再下降。

去精读 · 往后连

精读:3B1B 第 2 章把这个循环讲成动画。往后连:第 7 章神经网络的「反向传播」,就是第③步「算梯度」的高效做法——上万个参数一次性算出各自的坡度。这个循环一模一样。

五块地基到齐了。下面用十几行 NumPy,手写一个最小的梯度下降,亲眼看损失一步步降下去。

12实战:手写一次梯度下降

不用任何机器学习库,就用 NumPy,让程序自己「学」出一堆数的平均值——因为「让均方误差最小的那个数」正好就是平均值。看损失怎么一步步降到最低:

gradient_descent.pypython
import numpy as np

data = np.array([2.0, 4.0, 6.0, 8.0])   # 真实答案(平均值应是 5)
guess = 0.0            # ① 随便设的参数(我们猜的"平均值")
lr = 0.1               # 学习率:每步迈多大

for step in range(20):                  # 迭代 20 步
    loss = np.mean((guess - data) ** 2) # ② 算损失:均方误差
    grad = np.mean(2 * (guess - data))  # ③ 算梯度:损失对 guess 的坡度
    guess = guess - lr * grad           # ④ 顺坡下山:往下挪一小步
    print(f"step {step:2d}  guess={guess:.3f}  loss={loss:.3f}")

# guess 会一步步逼近 5.0,loss 一步步逼近 0

读一遍:loss 是损失;grad 是梯度(坡度);guess = guess - lr * grad 就是顺坡下山挪一步,lr 是学习率;整个 for 是训练循环,每轮是一次迭代。跑一下,我会看到 guess 从 0 一步步爬到 5、loss 一步步掉到 0——这就是训练,神经网络只是把这套放大到上百万个参数。

进阶挑战

改改看

①把 lr 改成 0.01,观察 loss 降得多慢(学习率太小)。②改成 1.1,看 loss 怎么炸开(学习率太大、发散)。③把打印的 loss 收集进一个列表,想象把它画成曲线——那就是训练时最该盯的「损失曲线」。

14常见误区 · 实际情况

表 3 · 五个新手误区
我可能以为实际情况
模型是一步算出最优解的是一小步一小步「挪」出来的,靠梯度下降迭代千万次逼近最优。
梯度是很玄的数学梯度就是坡度:告诉我最陡的下坡朝哪、有多陡。顺着它往下走就对了。
学习率越大训练越快太大越过谷底、来回蹦甚至发散。要「刚好」,靠看损失曲线调。
epoch 越多越好过了头会过拟合。看验证集:开始变差就该停(早停 early stopping)。
神经网络的训练是另一套还是这套循环。反向传播只是「高效算梯度」的方法,下山逻辑一模一样。

15自测 · 思考题

  1. 一句话定义。用「下山」解释:损失、梯度、学习率各对应下山时的什么?
    参考答案

    损失=我所在的海拔(越低越好);梯度=脚下坡度(最陡下坡朝哪);学习率=每步迈多大。

  2. 诊断。训练时损失一开始猛降,后来忽上忽下、降不动了,最可能是什么问题?
    参考答案

    学习率偏大,在谷底附近来回横跳。可调小学习率,或用会自动衰减学习率的优化器。

  3. 区分。数据 1000 条、每批 100 条,跑 5 个 epoch,一共挪了多少步(迭代)?
    参考答案

    每 epoch 有 1000/100=10 步,5 个 epoch 共 50 步。

  4. 连回上一章。训练损失一直降、但测试损失开始回升,这是第 5 章的什么现象?
    参考答案

    过拟合。训练久了在背训练数据的噪声;该早停,或简化模型/加正则。
