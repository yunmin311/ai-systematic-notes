五步循环:手写版和 PyTorch 版并排

这个实验只做一件事:把同一个训练过程写两遍——一遍纯手写(自己算梯度),一遍用 PyTorch(框架算梯度),然后对比两者的结果和代码量。跑完就知道框架到底替代了哪一步。

跑完这个实验,会亲眼看到

  • 手写梯度下降的每一行分别对应五步里的哪一步
  • 同一个任务,PyTorch 版少写了多少行、少写的是哪些行
  • 两版跑出来的参数几乎一致——框架没有变魔术,只是替代了求导
  • 漏掉 zero_grad() 会发生什么(亲手制造一次)

5亲手制造一次经典 bug

把 opt.zero_grad() 注释掉,看会发生什么。这是新手最常犯的一个错。

step3_nograd.py 
点「▶ 运行」后,输出显示在这里
应该看到前几步的 w.grad 绝对值一路变大(梯度在累加,不是每步重算), 20 步之后的 w、b 明显偏离 3 和 2,或者直接发散成很大的数 / nan。 关键:整个过程不报错。

PyTorch 的梯度是累加的:backward() 把新算出的梯度加到 .grad 上,而不是覆盖。不清零,第 n 步用的其实是前 n 步梯度的总和,方向被历史带偏。这个 bug 不报错,只是训练不收敛——正是最难查的那一类。
