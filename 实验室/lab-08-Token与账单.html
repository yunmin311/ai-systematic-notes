Token 与账单:一次功能到底多少钱

把「这个功能贵不贵」变成一道能算的算术题:中英文各消耗多少 Token、输入和输出的单价差多少倍、缓存能省下多少。这个实验里的计数是估算,精确计数要用官方分词器,第 3 步给了本机做法。

跑完这个实验,会亲眼看到

  • 同一段话中英文的 Token 数之比
  • 输出比输入贵好几倍这件事,在总账里占多大比重
  • 长对话里「重读历史」的花费占比
  • 估算和精确计数的差别有多大,以及什么时候必须用精确的

2要看清的那件事

把成本从「感觉很贵」变成一个能写在纸上的数,并且知道这个数里哪一项是大头。

3估一段话有多少 Token

用一条粗略规则估算:英文约 4 个字符 1 个 Token,中文约 1 个字 1.5 个 Token。这是估算,不是精确值。

step1_count.py 
点「▶ 运行」后,输出显示在这里
应该看到中文: 42 字符 → 约 58 Token 英文: 131 字符 → 约 33 Token 中/英 Token 数之比: 1.76 (同一个意思,中文通常更费 Token——D12 第 10 节讲了原因)

中文更费 Token 的原因在 D12:训练语料以英文为主,英文常见词被合并成整块,中文常常一两个字就要一个 Token。这直接影响账单和上下文窗口能装多少内容。

4算一次功能的月账

一个功能:每次输入 2000 Token、输出 300 Token,每天调用 1000 次。输入 $0.3/百万,输出 $1.5/百万。

step2_bill.py 
点「▶ 运行」后,输出显示在这里
应该看到每天输入 2.0M Token → $0.60 每天输出 0.3M Token → $0.45 每天合计 $1.05 每月约 $31 输出量只有输入的 15%,但花费占比: 43% 原因:输出按 D17 说的逐个生成、无法并行,单价贵 5 倍 若 1500 Token 的系统提示走缓存:每天输入 $0.20(原 $0.60) 每月省下约 $12

两个反直觉的数:①输出只占 15% 的量,却占了 43% 的钱——因为单价差 5 倍;②缓存能砍掉输入侧的大头,而缓存生效的前提是前缀不变(U02 第 3 节)。

5长对话:钱花在重读上

一场对话每轮只新增 1000 Token,但每一轮都要把之前的全部重读一遍。算算十轮下来的账。

step3_reread.py 
点「▶ 运行」后,输出显示在这里
应该看到轮次 本轮读入 Token 累计读入 1 1,000 1,000 2 2,000 3,000 5 5,000 15,000 10 10,000 55,000 十轮里真正「新写」的内容: 10,000 Token 十轮里实际被读入的总量: 55,000 Token 重读占比: 82% 按 $0.3/百万计,这一场对话的输入侧花费 $0.0165

重读占比随轮数继续上升——上下文攒到 100k 时,九成以上的钱买的是「把说过的话再读一遍」。所以「让回答简短点」几乎省不下钱,真正的杠杆是让上下文别那么长,或者让重读走缓存。

7排错

现象原因怎么办
估出来的 Token 数和官方计数对不上这是粗估,不是分词器本机装 pip install tiktoken,用 tiktoken.get_encoding("cl100k_base").encode(text) 得到精确值
单价对不上各家、各型号价格不同且会变把 IN_PRICE/OUT_PRICE 换成实际用的那个模型的价
数字看着不像钱单位是每百万 Token除以 1e6 那一步就是在换算单位
