最小 harness:二十行里的每一个治理抓手

这个实验不调任何 API、不花一分钱——模型部分用一个写死的桩替代。要看的不是模型有多聪明,而是外面那圈框架都管了什么:工具注册、循环、步数上限、日志、危险动作拦截。这五样,正是治理能落手的地方。

跑完这个实验,会亲眼看到

  • 一个能跑的 agent loop,总共二十来行
  • 「自主」不来自模型,来自这个循环——把循环去掉就只剩一问一答
  • 步数上限拦住死循环的那一刻
  • 危险动作在执行前被挡住,而不是靠提示词请它别做
配套哪一章

配套 A05 的 agent loop 与治理抓手、U03 的规则五级强度阶梯。做完可以接 项目 P6。

1怎么跑

方式 A · 页面内运行器:每段代码旁边有「▶ 运行」,用的是 Pyodide——一个跑在浏览器里的真实 Python,不是模拟输出。首次点击要下载运行时,约 10–20 秒,需要联网。用到第三方库时会自动装包,第一次会再多等一会儿。

方式 B · 本机终端:代码同时放在 实验室\code\lab09\ 下,可以直接 python step1_loop.py。本机跑得更快,而且能改文件、能存结果。

2要看清的那件事

把 A05 那句话变成能跑的代码:模型只是发动机,真正让它能干活也真正能被治理的,是外面那圈工程外壳。

3循环本身

模型用一个桩函数代替:它按固定剧本请求调工具。重点看循环怎么把「想 → 做 → 看」串起来。

step1_loop.py 
点「▶ 运行」后,输出显示在这里
应该看到[1] 调用 read_file('notes.md',) → [notes.md 的内容:共 3 行] [2] 调用 word_count('[notes.md 的内容:共 3 行]',) → 4 个词 [3] 完成 → notes.md 大约有 4 个词。

把 for 循环删掉,这就退化成一次普通问答。「自主」不是模型的属性,是这个循环给的。另外注意 TOOLS.get 那一行:工具白名单——没注册的东西模型再想调也调不到,这是第一个治理抓手。

4两道闸:步数上限与危险动作拦截

换一个会犯错的桩:它陷入死循环,而且中途试图删文件。看两道闸分别在哪一刻起作用。

step2_guard.py 
点「▶ 运行」后,输出显示在这里
应该看到[1] read_file → [notes.md 的内容] [2] read_file → [notes.md 的内容] [闸 2] 危险动作 delete_file 被拦下:执行前需要人确认 [4] read_file → [notes.md 的内容] [闸 1] 步数到上限 4,强制停止 ---- 日志(第五个抓手)---- 20:39:49 call read_file 20:39:49 call read_file 20:39:49 blocked delete_file 20:39:49 call read_file 20:39:49 halt max_steps=4

两道闸的位置很关键:危险动作是在执行前被挡住的,不是执行完再回滚。把 APPROVE 改成 True,删除就会真的发生——这一行就是「人点头」这个环节在代码里的样子。
五个抓手到齐了:工具白名单、步数上限、危险动作确认、全程日志、失败可回滚(最后一项这里用「拒绝后继续」代替)。这正是 A05 第 6 节说的、治理该固化的东西。

5自己改一改

改完再跑一次,预测一下会变成什么样

① 把 MAX_STEPS 改成 100,再跑第 2 步——死循环会跑到什么时候才停?这说明步数上限拦的是什么。
② 把 APPROVE 改成 True,对比日志的差别。真实系统里这个开关该由谁来拨?
③ 在 TOOLS 里加一个 send_email,让桩模型去调它——不加进白名单会怎样?加进白名单但不加进 DANGEROUS 又会怎样?

6排错

现象原因怎么办
第 1 步报 IndexError剧本用完了但循环还在跑这正好演示了步数上限的必要性;第 2 步加上了闸
第 2 步一直不停MAX_STEPS 被改大了这是第 1 个改一改要看的现象,不是 bug
日志是空的所有动作都在闸前被拦下了看 blocked 那几行;被拦也是要记的

7收口

这二十行就是一个 agent 的骨架。真实的 harness 只是把每一块做厚:工具更多、循环更聪明、上下文要管理、日志要落盘。但治理能落手的位置,一个不多一个不少,就是这五处。
