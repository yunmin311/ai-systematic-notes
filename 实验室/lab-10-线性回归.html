线性回归:闭式解、梯度下降和一行 sklearn

同一个问题用三种办法解一遍:闭式解一步算出答案,梯度下降一步步挪过去,sklearn 只要一行。三者的答案必须一样——如果不一致,一定是有地方算错了,而不是「方法不同所以结果不同」。这是「模型-损失-训练」三件套最干净的一次示范。

跑完这个实验,会亲眼看到

  • 闭式解直接给出 w 和 b,残差之和恰好为 0
  • 梯度下降的 MSE 从 1.0 掉到 0.0002,而且先快后慢
  • 手写梯度下降和闭式解的结果,小数点后 4 位一致
  • 为什么原始尺度下必须标准化——w 的梯度是 b 的上百倍
  • 加第二个特征时系数会「变怪」,这是多重共线性,不是 bug

2要看清的那件事

把 D01 那句话变成能跑的数:学习就是把 w、b 这两个旋钮,调到让 MSE 最小。闭式解是直接解出那个最小的位置;梯度下降是一步一步摸过去。路径不同,终点必须是同一个。

3闭式解:一步算出来

最小二乘有解析解,不用迭代。w = Σ(x−x̄)(y−ȳ) / Σ(x−x̄)²,b = ȳ − w·x̄。这一节先把「正确答案」算出来,后面两步都拿它当基准。

step1_closed_form.py 
点「▶ 运行」后,输出显示在这里
应该看到闭式解直接给出: w = 2.7565 b = 16.0561 也就是: 总价 ≈ 2.76 × 面积 + 16.1 面积 真实 预测 残差(预测-真实) 50 155.0 153.9 -1.12 60 182.0 181.4 -0.55 80 235.0 236.6 +1.58 100 290.0 291.7 +1.71 120 348.0 346.8 -1.16 150 430.0 429.5 -0.46 MSE(均方误差) = 1.42 残差之和 = 0.00 ← 几乎为 0,这是最小二乘的必然结果 外推:95㎡ → 277.9 万元

两个点值得盯一下。残差之和恰好是 0——不是凑巧,是最小二乘的必然:如果残差之和不为 0,把 b 挪一点就能让 MSE 更小,那它就不是最小了。MSE 只有 1.42,相当于每套房平均差一万两百块,这是因为这份数据是照着直线抖出来的;真实数据的 MSE 会大得多。

4梯度下降:一步步挪过去

闭式解快,但特征一多、模型一复杂就没有解析解了,那时只能靠梯度下降。这一节手写它,看 MSE 怎么一轮轮掉下去。

step2_gradient_descent.py 
点「▶ 运行」后,输出显示在这里
应该看到轮次 w b MSE dw 0 0.0000 0.0000 1.0000 -1.9998 10 0.8926 0.0000 0.0117 -0.2147 20 0.9884 0.0000 0.0003 -0.0231 30 0.9987 0.0000 0.0002 -0.0025 40 0.9998 0.0000 0.0002 -0.0003 50 0.9999 0.0000 0.0002 -0.0000 60 0.9999 0.0000 0.0002 -0.0000 换算回原单位: w = 2.7565 b = 16.0564 第 1 步闭式解: w = 2.7565 b = 16.0561 两者相差: w 0.00000 b 0.00032

三条要看出来的:
① 先快后慢。前 10 轮 MSE 从 1.0 掉到 0.0117,后 50 轮只从 0.0003 挪到 0.0002。因为梯度本身在变小——越接近谷底坡越平。这是所有梯度下降的共性。
② b 一直是 0。不是没更新,是标准化之后 y 的均值就是 0,截距在这个尺度下天然为 0。换算回去 b 就回来了(16.0564)。
③ 和第 1 步对上了。w 一模一样,b 差 0.0003。闭式解和梯度下降给出同一个答案——它们不是两种模型,是解同一个问题的两条路。

5sklearn:一行,以及加一个特征会怎样

真干活当然不手写。看 sklearn 的答案,顺手加第二个特征,撞见一个很多人第一次都会误解的现象。

step3_sklearn.py 
点「▶ 运行」后,输出显示在这里
应该看到sklearn 给出: w = 2.7565 b = 16.0561 第 1 步手算: w = 2.7565 b = 16.0561 R² = 0.999843 ← 1.0 表示完全贴合 两个特征时: 面积系数 2.759 卧室系数 -0.114 截距 16.159 R² = 0.999843 注意卧室数的系数——它很小甚至可能为负,因为面积和卧室数高度相关。 这不代表卧室不重要,是多重共线性的典型表现;这时单个系数没法单独解读。

三行数字完全一样——手算、梯度下降、sklearn 三条路同一个终点,这才说明前面没算错。
加第二个特征那一段是关键:卧室数的系数是 −0.114,难道多一间卧室房子还更便宜?不是。面积和卧室数在这份数据里几乎一起涨,模型没法分清「面积涨带来的涨价」和「卧室多带来的涨价」该各算多少,于是把权重在两者之间随便一分。这就是多重共线性:系数还在,但单个系数不再能单独解读。R² 一点没变,说明模型预测能力没变差,坏的只是「可解释性」。

6自己改一改

改完再跑一次,预测一下会变成什么样

① 把第 2 步的 lr 从 0.1 改成 1.0,会看到 MSE 不降反升甚至发散。这说明学习率是什么的上限。
② 把 lr 改成 0.001,60 轮之后 w 到多少?和第 1 步差多少?——这就是「训练没训够」。
③ 删掉第 2 步的标准化(直接用 X、y),lr 保持 0.1 再跑。会看到 w 直接飞掉,而 b 几乎没动——这就是注释里那句「一个学习率顾不住两个旋钮」的现场。
④ 在第 3 步的数据里加一套 300㎡ 的豪宅,看 w 和 MSE 怎么变。一个点能把整条线拽多少?

7排错

现象原因怎么办
第 3 步报 ModuleNotFoundError: sklearn页面内运行器第一次用这个包等它自动装完再点一次;本机跑就 pip install scikit-learn
第 3 步报 ValueError: Expected 2D arraysklearn 要二维的 X用 .reshape(-1, 1) 把一维列变成一列二维
第 4 步 MSE 变成 nan 或越来越大学习率太大,一步跨过了谷底并且越跨越远把 lr 调小一个数量级(0.1 → 0.01 → 0.001)
换算回去的 b 和闭式解差很多迭代轮数不够,还没收敛把 range(0, 61) 改大;看 dw 那列是不是已经接近 0
自己改数据时 R² 变成负数模型比「直接猜均值」还差,通常是特征和目标毫无关系不是 bug;换一组真的有关系的量试试

8收口

「模型-损失-训练」这三件套,在这个实验里第一次完整跑通:模型是 ŷ = w·x + b,损失是 MSE,训练是「算梯度 → 往反方向挪一小步」。后面所有模型——逻辑回归、神经网络、Transformer——换的都是前两项,第三项这套动作从没变过。把这一节的手写循环看懂,后面几十章的训练代码就都是它的变体。
