实验室 · lab-15 · 配套 D13 Embedding 与向量空间 · 只要 numpy

Embedding:让「意思像不像」变成一个可以算的数

这一节做两件事。第一件:同一个问题分别用余弦和欧氏距离算,看它们给出相反的答案——然后明白为什么文本检索默认用余弦。第二件:用 12 句自己编的语料、一个共现矩阵、一次 SVD,真的「学」出词向量出来,看猫狗兔子是怎么自己聚到一起的。全程不需要任何预训练模型。

跑完这个实验,会亲眼看到

  • 余弦说 A 离 B 更近,欧氏距离说 A 离 C 更近——两个度量直接打架
  • 欧氏距离错在把「文章有多长」也算进了「像不像」
  • 12 句语料 + 一次 SVD,猫、狗、兔子就自动互为最近邻
  • 鱼、骨头、胡萝卜聚成另一堆——没人告诉程序它们都是吃的

2要看清的那件事

D13 那句话是:意思变成位置,「像不像」变成「近不近」。但「近」有很多种算法,选错了整套检索就都是歪的。这一节先把选哪个度量说清楚,再亲手把「位置」造出来。

3余弦还是欧氏:两个度量给出相反答案

三篇文档,词频向量。看 A 到底和谁更像。

step1_cosine.py 
点「▶ 运行」后,输出显示在这里
应该看到三篇文档的词频向量(维度: 猫 / 狗 / 鱼): A = [10 10 0] 长文·只讲猫狗 B = [1 1 0] 短文·只讲猫狗 C = [8 8 9] 长文·猫狗+鱼 A 和谁更接近?两种度量给出相反的答案: 组合 余弦相似度 欧氏距离 A–B 1.000 12.728 A–C 0.783 9.434 余弦: A–B = 1.000 > A–C = 0.783 → B 更近,判对了 欧氏距离: A–B = 12.73 > A–C = 9.43 → 说 C 更近,判错了 欧氏距离为什么会判错?因为它把「向量有多长」也算进去了。 B 是短文,词频整体偏小,于是它离 A 的直线距离被拉得很远—— 可 B 和 A 的方向完全一致,讲的是一模一样的事。 文本里「长度」来自篇幅、重复次数、文档粗细,和「在讲什么」无关。 所以判断意思像不像要用余弦(只看方向,不看长度),这也是 RAG 向量检索的默认度量。

这个例子把差别推到极端,所以答案特别清楚:余弦只看方向,欧氏距离把长度一起算进去。现实中不会这么夸张,但方向是一样的——一篇文章扩写一倍,主题没变,欧氏距离却会明显变大。所以做向量检索时,存向量之前通常还要做归一化(把长度统一成 1),那样余弦和内积就等价了,检索也更快。
顺带记住一个坑:余弦判断不了「几乎没有共同词」的情况。两个向量只要方向一致,哪怕内容都很稀疏,相似度也会很高。所以真实的混合检索常常是「向量 + 关键词」一起用。

4从共现矩阵里长出词向量

下面这段没有用任何现成的词向量。语料只有 12 句,而且是代码里现编的。看它能不能自己发现「猫和狗是一类」。

step2_vectors.py 
点「▶ 运行」后,输出显示在这里
应该看到语料 12 句,词表 9 个词 前 4 句: 猫 吃 鱼 / 猫 吃 骨头 / 猫 吃 胡萝卜 / 狗 吃 鱼 共现矩阵(行 = 当前词,列 = 它的邻居): 猫 狗 兔子 鱼 骨头 胡萝卜 猫 0 0 0 1 1 1 狗 0 0 0 1 1 1 兔子 0 0 0 1 1 1 鱼 1 1 1 0 0 0 骨头 1 1 1 0 0 0 胡萝卜 1 1 1 0 0 0 注意 猫、狗、兔子 三行的数字完全一样 —— 它们在语料里的位置是等价的。 前两个奇异值 9.30 / 6.15 承载了矩阵的主要结构。 每个词的最近邻居(余弦相似度): 猫 → 兔子 1.000、狗 1.000、胡萝卜 0.998 狗 → 兔子 1.000、猫 1.000、胡萝卜 0.998 兔子 → 狗 1.000、猫 1.000、胡萝卜 0.998 鱼 → 胡萝卜 1.000、骨头 1.000、兔子 0.998 骨头 → 胡萝卜 1.000、鱼 1.000、兔子 0.998 胡萝卜 → 骨头 1.000、鱼 1.000、兔子 0.998 吃 → 宠物 0.953、是 0.953、胡萝卜 0.400 值得盯的几行: · 猫、狗、兔子互为最近邻 —— 没人告诉模型它们都是动物, 只因为它们出现在同样的句式位置,坐标就长到了一起。 · 鱼、骨头、胡萝卜 也聚在一起 —— 它们是「被吃的那个」。 · 但「吃」的最近邻是 宠物 和 是(0.953),不是任何一类食物。 它和每个动物、每种食物都连过一次,连得太均匀,反而谁也不偏向—— 这也说明:一个词连接范围太广时,它的坐标会变得「中庸」,判别力反而弱。 这就是 Embedding 的原理:统计谁和谁一起出现,相似的上下文长出相似的坐标。 真实词向量只是把语料从 12 句换成几万亿句,把维度从 2 换成几百上千。

整段的机制只有三步:①数共现 → ②SVD 压到低维 → ③算余弦。没有字典、没有人工标注、没有任何语言学知识,「动物」和「食物」这两个概念是自己冒出来的。
两个必须看清的地方:共现矩阵里猫、狗、兔子三行完全一样,因为它们的位置在语料里是对称的——这一行数字就是它们的「坐标来源」。而 SVD 做的事,就是把「谁和谁一起出现」这张稀疏的大表,压成每个词的一小串坐标,同时尽量保住原来的结构。真实词向量(word2vec、BERT 的 embedding)换的是统计方法和语料规模,这三步的精神没变。
最后那条关于「吃」的观察也很有用:它提醒: 词向量不是越连越多就越好,连接范围太广的词(比如「是」「的」)会丢判别力。这也是为什么检索时常常要把这种高频虚词先去掉。

5自己改一改

改完再跑一次,预测一下会变成什么样

① 第 2 步把 WIN 从 2 改成 1。共现矩阵会变成什么样?动物和食物还会连上吗?(窗口 1 时「猫 吃 鱼」里猫和鱼就不在窗口内了)
② 第 2 步在语料里加一句 "猫 追 老鼠" 再跑。猫的邻居会变吗?它和狗还一样近吗?这就是「语料决定词义」——改数据比改模型管用。
③ 第 2 步把 emb = U[:, :2] * S[:2] 改成只取 U[:, :1](1 维)。再跑一次看邻居——一维够不够把两类分开?
④ 第 1 步把 B 改成 [10, 10, 0](和 A 一样长)。这时余弦和欧氏距离还打架吗?——长度拉平之后,两个度量就一致了。这正是「先归一化再比对」的道理。
⑤ 第 2 步把 np.linalg.svd(C) 换成对 C @ C.T 做特征分解(np.linalg.eigh),再看邻居列表。结果应该基本相同——SVD 和 PCA 在数学上是同一件事的两面,只是一个从左切、一个从右切。

现象原因怎么办
报 LinAlgError: SVD did not converge共现矩阵全 0(语料被改空了,或窗口设成 0)确认语料非空、WIN 至少为 1
所有相似度都接近 1.000语料太小、结构太规整,所有词几乎等价不是 bug;加几句打破对称的话再看(见改一改 ②)
邻居列表里出现 吃 是 这类虚词它们连接范围最广,SVD 之后落在中间不是 bug;真实检索里会先用停用词表滤掉
除零警告 RuntimeWarning: invalid value某个词的向量长度是 0(它没跟任何词共现过)检查语料里是不是有孤立的词
数字和这里对不上语料被改过,或 numpy 版本的 SVD 符号约定不同符号翻转不影响相似度;看「谁跟谁近」这个结论一致即可

7收口

D13 说「意思变成位置」,这一节把这个「变成」的过程跑了一遍:数共现 → 压维度 → 算余弦。真实词向量规模大得多,但没有任何魔法——它们也是从「谁和谁一起出现」里长出来的,只是见的语料多几亿倍。
理解这一点有个很实际的用处:当检索效果不好时,就知道该往哪儿调——是切块切坏了(数据)、语料不对(数据)、还是相似度算法选错了(度量),而不是笼统地觉得「模型不行」。
