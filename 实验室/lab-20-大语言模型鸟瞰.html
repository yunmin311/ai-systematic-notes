预测下一个词:把整个大模型缩到能用眼睛看完

第 8 章说大模型只做一件事:给定前面的文字,预测下一个最可能的 token,接上去,重复。这一节用 10 句话造一个能看全的语言模型——学到的表能一屏打出来,接龙能一句句跟读。然后再看 temperature:它一点都没改模型学到了什么,只改了「从分布里怎么抽」,输出就从完全确定变成了五花八门。

跑完这个实验,会亲眼看到

  • 一个语言模型学到的东西,就是一串「某个词后面可能跟什么」的概率
  • 同一个起点「猫」,接龙三次各不相同——因为每步都是从分布里抽的
  • 温度 0.2 时首选词占 99.2%,温度 5.0 时只占 38.4%
  • 但那张概率表从头到尾没变过——温度只作用于采样
  • 抽 200 次验证:温度 0.1 时首选 100%,温度 5.0 时只剩 39.5%

2要看清的那件事

「大模型」三个字容易被神化。把词表缩到 12 个词、语料缩到 10 句之后,机制是完全一样的——一样到可以逐句读懂它为什么接出这个词。这一节要看的就是这个机制,以及 temperature 在链条的哪一环动手。

3预测下一个词

先统计「谁跟在谁后面」,然后让模型从这个统计里接龙。这张表就是它的全部知识。

step1_next_word.py 
点「▶ 运行」后,输出显示在这里
应该看到模型学到的是这样一张表(每个词后面可能跟什么): 猫 → 喜欢(3/5)、抓(1/5)、在(1/5) 喜欢 → 吃(2/6)、睡(1/6)、晒太阳(1/6)、跑(1/6)、摇(1/6) 吃 → 鱼(1/2)、骨头(1/2) 狗 → 喜欢(3/5)、看(1/5)、在(1/5) 让它接龙三次(起点都是「猫」): 1. 猫 喜欢 跑 步 [句尾] 2. 猫 喜欢 睡 觉 [句尾] 3. 猫 喜欢 摇 尾巴 [句尾] 三次结果不一样,但每次都通顺——因为模型输出的是概率分布, 每一步都是从分布里抽一个,抽到什么有随机性。 这就是同一个问题每次答案会变的原因:不是它「改主意」了,是采样在起作用。 那句 [句尾] 也值得注意:词表里没有词的后面什么也不跟,模型就停在那里。 真实模型专门有一个「结束」符号来表示该收尾了—— 否则它会一直往下编,永远停不下来。 真实的大语言模型做的还是同一件事,只是三样东西被放大了: · 表从「上一个词 → 下一个词」升级成「前面所有词 → 下一个词」 · 词表从 12 个词变成几万到十几万个 token · 参数从这张几百个数的表变成几千亿个权重 机制没变:给定前面的文字,算下一个词的概率,采样,接到末尾,重复。

那张表就是「模型的知识」——三行数字,一眼看完。注意「喜欢」后面有 5 种可能,而「吃」后面只有 2 种:语料里怎么说,它就怎么学。大模型也是一样,只是它那张表有几万亿个格子。
三次接龙都从「猫 喜欢」开始,结果分别是"跑 步""睡 觉""摇 尾巴"——这三次都不是模型改主意,是每步的采样抽到了不同的词。所以「同一个问题问两遍答案不一样」不是故障,是它在按设计工作。
[句尾] 那一行也很实在:模型在「鱼」「觉」「步」这些词后面学不到任何后继,就停住了。真实模型靠一个专门的结束符号来收尾——没有它,模型会一直编下去停不下来。

4temperature:只改怎么采,不改学到了什么

同一个分布,加不同温度重新采样。看概率怎么变形、以及真抽 200 次的结果。

点「▶ 运行」后,输出显示在这里
应该看到模型认为「猫」后面最可能跟的词: 喜欢 60.0% ████████████████████████ 抓 20.0% ████████ 在 20.0% ████████ 同一个分布,加上不同温度之后(模型本身一点没变): 温度 喜欢 抓 在 熵(越高越随机) 0.2 99.2% 0.4% 0.4% 0.053 0.5 81.8% 9.1% 9.1% 0.600 1.0 60.0% 20.0% 20.0% 0.950 2.0 46.4% 26.8% 26.8% 1.062 5.0 38.4% 30.8% 30.8% 1.093 温度不改变模型学到了什么,只改变「从分布里怎么抽」。 T < 1 分布变尖 —— 高概率的词更容易被抽中,输出更确定、更保守 T = 1 原样采样 T > 1 分布被抹平 —— 低概率的词也有机会,输出更发散、更容易跑偏 T → 0 退化成「永远选概率最大的那个」,同一个问题每次答案都一样 每种温度下真抽 200 次,看首选词占了多大比例: (候选只有 3 个,所以别数「出现几种」——那个数最多到 3,看不出差别;要看占比) T=0.1 首选「喜欢」占 100.0% (喜欢×200) T=0.5 首选「喜欢」占 81.5% (喜欢×163、抓×19、在×18) T=1.0 首选「喜欢」占 59.5% (喜欢×119、在×46、抓×35) T=2.0 首选「喜欢」占 53.0% (喜欢×106、在×48、抓×46) T=5.0 首选「喜欢」占 39.5% (喜欢×79、在×71、抓×50) 这就是 API 里那个 temperature 参数的全部含义: 调低 → 稳定、可复现,适合抽取信息、写代码、做分类; 调高 → 多样、有惊喜,适合头脑风暴、写文案; 同一个问题答案飘忽不定,多半是温度开高了 —— 它是采样,本来就不保证一样。

两件事必须分清。①模型本身一点没变。那张概率表(60% / 20% / 20%)从头到尾是同一个——温度只是在采样那一步把对数概率除以 T 再归一化。所以调温度不会让模型变聪明,只会让它更敢赌或更保守。
②温度和「确定性」的关系是单调的,而且可以量。看最后一列熵:0.2 时 0.053(几乎不随机),5.0 时 1.093(接近均匀分布)。抽 200 次的实测也对上了:温度 0.1 时首选词占 100%,温度 5.0 时只剩 39.5%。
这份实测还有个附带结论:温度调到 0.1 时,"同一个问题每次答案一样"是可以做到的——这解释了为什么写代码、做分类这类任务都建议把温度调到接近 0。反过来,感觉输出飘忽不定,先去检查温度,而不是怀疑模型坏了。

5自己改一改

改完再跑一次,预测一下会变成什么样

① 第 1 步把起点从「猫」改成「狗」,再跑三次。出现「狗 喜欢 跑 步」的概率大吗?——看那张表里「喜欢」后面哪个词占 2/6 就知道。
② 第 1 步在语料里加一句「猫 喜欢 吃 猫粮」,再跑。表里「喜欢」那一行的概率怎么变?这就是「投喂数据改变模型行为」的最小例子。
③ 第 1 步把 np.random.choice 换成 np.argmax(永远选概率最大的)。接龙还会变吗?——这就是贪心解码,也叫温度 0。
④ 第 2 步把温度列表改成 [0.01, 0.05] 再跑,看首选占比是不是都接近 100%。这解释了为什么设 0.1 和设 0.01 感觉没差别。
⑤ 第 2 步把语料改成只有「猫 喜欢 吃 鱼」一句(分布变成 100%/0%/0%)。这时温度还起作用吗?——温度改不动「模型本来就只有一个选择」的情况。

6排错

现象原因怎么办
报 ValueError: a must be greater than 0某个词后面没有后继,概率数组是空的代码里那句 if len(keys) == 0: break 就是处理它的;真实模型靠结束符号
三次接龙结果完全一样np.random.seed(0) 固定了随机数,而且每步分布很尖不是 bug;去掉 seed 或调高温度去看差异
温度改成 0 报除零错除以 0温度取一个很小的正数(如 1e-6)就是实际上的温度 0
长句子接不出有意义的上下文这是二元模型,只看上一个词,不看整句不是 bug;真实模型用的是「前面所有词」,见 lab-17
熵那一列看不懂熵是「有多随机」的度量,均匀分布最大只用来看趋势:温度升,熵升,就对了

7收口

第 8 章那句「一个字一个字地接龙」,在这一节变成了三行能读懂的代码:算下一个词的概率 → 采一个 → 接到末尾。放大到几万亿字、几万 token、几千亿参数之后,机制一字未改。
理解了这一点,很多日常疑惑就自动有了解释:答案飘忽是采样;答非所问是概率分布学了不该学的东西;调温度不解决能力问题,只解决稳定性和多样性的取舍。下一节 lab-08 已经把「一个 token 多少钱」算过一遍,两者合起来就是「大模型是什么、以及它怎么计费」的完整答案。
