Agent 基础:工具、记忆、工作流

前三章的模型都是"问一次、答一次"。Agent(智能体)把它升级成:模型在一个循环里——想一步、决定调哪个工具(A02 的函数、A03 的检索、搜索、写文件……)、看结果、再想下一步,直到把任务办完。这一章讲清 agent 的四个零件(工具、记忆、循环、判断),以及一个关键的克制:能用固定流程解决的,别上 agent。这是通往下一章"harness/底层框架"的正门。

图解骨架约 45 分钟,动手 + 精读约 5~7 小时。所有零件都用前三章作对照:工具=A02 函数调用、检索工具=A03 RAG、上下文=A01。每个新词当场白话解释。

读完这一章,我脑子里会立起来的骨架

  • Agent 是什么——模型 + 一个循环 + 一批工具,能自己多步做事
  • 工具——agent 的手脚:把「只会说」变成「能动手」
  • 记忆与状态——记住做过什么、上一步结果(短期在上下文,长期存外部)
  • 规划循环 ReAct——想→做→看→再想,循环到完成(核心)
  • 何时该用/不该用——能用固定工作流就别上 agent(贵、慢、不稳)

4一句话本质

Agent:把模型放进一个循环,让它自己决定下一步调哪个工具、看到结果后再决定下一步,如此往复,直到任务完成——从"回答问题"变成"完成任务"。

普通问答是一锤子买卖:我问,它答,结束。但很多真实任务不是一句话能答完的——"帮我查这周三个城市的天气再订最便宜的酒店",需要多次查、比、算。Agent 的办法:给模型一批工具(它能调用的动作),再套一个循环——模型每轮输出"我要调哪个工具、传什么参数",程序执行、把结果喂回去,模型据此决定下一步,直到它说"办完了"。模型成了循环里的决策大脑,工具是它的手脚,循环给它多步行动的机会。这就是从 A02 的"单次调用"到"自主系统"的跃迁。

先看清楚:同一个问题,普通问答和 agent 的处理方式差在哪。

7Agent 是什么:从一次问答到一个循环

普通问答=一次输入到输出;agent=模型 + 一个循环 + 一批工具,能多轮自主行动。差别不在模型多聪明,在外面套没套那个循环。

关键要认清:agent 的"自主"不是模型自己长出来的,而是我用代码给它搭的循环给的。模型每一轮只做一件事——根据当前情况输出"下一步调哪个工具"。是外面的程序真正去执行工具、把结果拼回上下文、再让模型跑下一轮。所以 agent = 会决策的模型 + 会执行的循环。理解这一点,A05 讲 harness 就顺理成章:harness 就是这个循环 + 上下文管理 + 工具接线的总和。

循环里最实的一块,是模型能调的那批"工具"。

8工具:agent 的手脚

工具tools:agent 能调用的一个个动作——搜索、算数、查数据库、读写文件、调 API……就是 A02 的函数调用,只是给它一批让它自己挑。

模型本身只会生成文字,不能上网、不能算准数、不能改文件。工具就是把这些能力接给它:每个工具有名字、说明、参数(A02 讲的 schema),模型根据任务选一个、填好参数,程序执行后把结果告诉它。A03 的 RAG 检索,在 agent 眼里就是一个叫"查资料"的工具。工具的说明写得好不好,直接决定模型选得对不对——这和 A01 的提示词工程一脉相承。工具越强,agent 能干的事越多,但也越要防它乱调(见 A06 安全)。

多步行动就要记事:上一步查到了什么,不能转头就忘。

9记忆与状态

Agent 靠把历史累积在上下文里记事:每轮的想法、调过的工具、拿到的结果都留在上下文中,模型下一轮才知道"进行到哪了"。这叫状态。上下文放不下时,靠长期记忆(存外部、要用再取)。

短期记忆=当前上下文窗口(A01),装着这次任务的全过程;它有限,轮数一多就撑爆,所以要管理(A05 的核心话题之一)。长期记忆=把该记住的东西存到外部(文件、数据库、向量库),需要时再检索回来——注意,这本质就是 A03 的 RAG,只不过检索的是"agent 自己的历史/知识"。状态管理是 agent 稳不稳的命门:记乱了、记丢了,它就会重复劳动或前后矛盾。

工具、记忆到位,把它们转起来的引擎,就是那个循环——ReAct。

10规划循环 ReAct(核心)

ReAct = Reason(想)+ Act(做):模型先想一步(我该干嘛)→ 做(调一个工具)→ 看结果(observation)→ 拿结果再想下一步……循环到任务完成才收尾。这是绝大多数 agent 的骨架。

为什么要"想"这一步:如果模型闷头直接调工具,一步错步步错;让它每轮先把"当前该做什么、为什么"讲出来(哪怕只在内部),决策质量明显更高——这也接上了 A01 的"分步思考"。循环的每一轮把"想法 + 动作 + 结果"追加进上下文(第 9 节的状态),模型据此判断:还没完→继续下一轮;够了→输出最终答案。这个"想→做→看"的环,就是 A05 里 agent loop 的雏形,也是理解 Claude Code 这类工具怎么运转的钥匙。

去精读 · 往后连

精读:ReAct 论文图 1 对比"只推理/只行动/ReAct"三种,一眼看出为什么要合起来。往后连:A05 会把这个循环拆到底层——上下文怎么管、工具怎么用协议(MCP)接、多个 agent 怎么协作。

最后是最重要的判断:很多任务,其实不该上 agent。

11何时该用 agent、何时别用

Agent 强,但贵、慢、不稳(每轮都调一次模型,还可能绕远、卡循环)。能用固定工作流(workflow)解决的,就别上 agent。这是 Anthropic 反复强调的克制。

区分两个词:工作流 workflow=我预先把步骤写死的固定管线(第一步做 A、第二步做 B),路径可预测、便宜、稳;agent=让模型自己决定路径,灵活但不可预测。判据很简单:任务步骤固定、可预先编排 → 用工作流(比如 A03 那条 RAG 链就是工作流);步骤因情况而变、需要临场决策 → 才用 agent。现实里最好的系统常是"工作流为主,只在真需要判断的那一环嵌一小段 agent"。别因为 agent 时髦就到处用——它每多转一轮,就多一份成本、延迟和出错机会。

12组装:最简 agent loop

下面这段(化简的伪代码)就是几乎所有 agent 的心脏——它把前五块全串起来了:

agent_loop.pypython
def run_agent(task, tools, max_steps=10):
    messages = [{"role": "user", "content": task}]   # ③ 状态:一路累积在这

    for step in range(max_steps):                    # ④ 循环:给它多步机会
        # ① 模型这一轮:想 + 决定调哪个工具(工具清单来自 ②)
        reply = model.chat(messages, tools=tools)
        messages.append(reply)                        # 把这轮想法/决定记进状态

        if reply.tool_call is None:                   # ⑩ 判断:它说不用工具了 = 办完
            return reply.content                       # 输出最终答案,跳出循环

        # ② 做:程序真正执行模型选中的工具
        result = run_tool(reply.tool_call)
        # ③ 看:把工具结果喂回状态,下一轮模型据此再想
        messages.append({"role": "tool", "content": result})

    return "超过步数上限还没办完"                        # ⑪ 兜底:防死循环(见 A06)

逐行对照五块:messages 是状态/记忆(③),一路追加;for step 是循环(④),给它多步机会;model.chat(..., tools=...) 让模型想 + 选工具(①②);run_tool 是做,结果喂回(③)让它下一轮再想。tool_call is None 是它自己判断办完了。max_steps 是兜底闸——防止它卡进死循环(agent 最常见的翻车,A06 细讲)。真实框架(LangGraph 等)在这十几行上加了错误处理、并行、观测,但骨架就是它。

进阶挑战

想清楚三件事

①如果去掉 max_steps 这道闸,会发生什么坏情况?(提示:工具老是失败或模型判断不了"办完")②如果 messages 越滚越长、撑爆上下文窗口,我会怎么办?(这正是 A05 的上下文管理)③一个"查天气→订酒店"的任务,用这个循环走一遍,列出它每一轮的想/做/看分别是什么。

14常见误区 · 实际情况

表 2 · 五个常见误区
我可能以为实际情况
Agent 是一种更聪明的模型不是。它是"普通模型 + 我搭的循环 + 一批工具";自主来自循环,不是模型本身。
什么任务都该做成 agent步骤固定的任务用工作流更好——便宜、稳、可预测。能不用 agent 就不用。
Agent 会自己上网、自己算只有我给它接了对应工具才行;不给工具,它还是只会生成文字。
给它目标它就能一路办到底它会绕远、卡死循环、记乱状态;必须有步数闸、错误处理、观测(A06)。
Agent 和 RAG 是两回事RAG 常常就是 agent 手里的一个"查资料"工具;长期记忆本质也是 RAG。

15自测 · 思考题

  1. 一句话本质。agent 和普通问答最根本的区别是什么?
    参考答案

    普通问答一次结束;agent 把模型放进循环 + 给它工具,让它多轮自主行动直到办完任务。自主来自循环。

  2. 四个零件。说出 agent 的四个零件并各一句话。
    参考答案

    工具(能调的动作)、记忆/状态(累积历史)、循环 ReAct(想→做→看→再想)、判断(何时办完/该不该用 agent)。

  3. 该用哪个。"每天早上把三个固定网站的头条抓下来汇总"——用 agent 还是工作流?
    参考答案

    工作流。步骤固定、可预先编排,不需要临场决策,用 agent 只会更贵更不稳。

  4. 兜底。为什么 agent loop 一定要有 max_steps?
    参考答案

    防死循环:工具反复失败、或模型判断不了"办完",会无限转下去,烧钱又卡住。步数闸强制收尾。
