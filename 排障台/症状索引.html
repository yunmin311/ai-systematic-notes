症状索引

这不是讲义,是出事之后来查的。按症状找,右侧目录就是全部条目。每条四段:症状 / 底下发生了什么 / 当场怎么办 / 怎么让它别再犯。最后一段最重要——它把一次性的救火变成一条不会再犯的机制。

怎么用

从右侧目录里找最像的那条症状点进去。找不到就先去 U01 的六个怪现象对一遍——多数症状是那六个根因的变体。解决之后,把新的一条补进这里,尤其是「怎么让它别再犯」那一段。

1规则复述得出来,就是不照做

底下发生了什么规则进上下文只提高照做的概率,和「必须照做」之间没有强制环节。复述和照做是两次独立的生成。
当场怎么办先分清三层:根本没读到(问「现在生效的规则文件路径有哪些」)/ 读到了被稀释(看是第几轮开始违反的)/ 和别的冲突(直接问「这条和当前任务冲突吗」)。
怎么让它别再犯把规则升到脚本层或拦截层。能变成一个数的,写成校验脚本、交付前必跑、退出码非 0;不可逆动作直接在工具层拦住。详见 U03 第 3 节的五级阶梯。

2禁区规则和任务指令打架,它自己解释了一下就过去了

底下发生了什么冲突不表现为拒绝,表现为「重新理解了一下适用范围」——过程完全合理,结论是违规,而且这个新解释可能被顺手写进计划书当成既定事实。
当场怎么办把那条新解释单独拎出来,回到原始规则的原文逐字对照。凡是原文里没有的限定词,都是它自己加的。
怎么让它别再犯把「遇到规则冲突必须停下来问人、不许自己重新解释边界」写成一条硬规矩,并且放进拦截层——不是写进规则文件里指望它自觉。

3说「已完成」,一看文件没动

底下发生了什么「已完成」是生成出来的文字,不是执行回执。回执可能被上下文裁掉、被失败重试盖过、或者压根没调工具——三种情况下这句话都会照常出现。
当场怎么办不回「好的」,回「把改动过的文件和它们的最后修改时间列出来」。要客观痕迹,不要它的叙述。
怎么让它别再犯把交付格式固定成:必须带文件清单 + 时间戳 + 校验脚本的输出原文。「测试通过」四个字不算交付。见 U07 第 7 节。

4实跑测到的是旧构建

底下发生了什么产物没重新生成,或者生成到了另一个位置。表现有两种:改了却没变化,以及更坏的——没改却「通过」了。
当场怎么办先核构建号/提交号,确认测的是这一版,再看结果。顺序反了会浪费大量时间去查一个不存在的 bug。
怎么让它别再犯把版本号或提交号打进产物本身(页面页脚、启动日志、命令 --version),验收第一步核它。比每次都记得重新构建可靠。

5校验脚本全绿,内容却是错的

底下发生了什么脚本验的是形式(格式、结构、分布、链接)。没有任何形式指标能证明内容正确。一份产出可以完美通过全部自检,同时把概念讲错。
当场怎么办把内容那一半单独排一次:逐条对着上游材料核,找三类问题——和上游矛盾的 / 超出范围的 / 表述本身有错或有歧义的。
怎么让它别再犯交付时明说脚本验了什么、没验什么;内容核查要记清核了多少条、改了多少条、每类各几条。「看过一遍」不是验收结论。

6批量生成的东西有系统性偏差

底下发生了什么批量生成会沿着同一个分布中心走,于是偏差是成片的而不是随机的。抽查三处全落在好的那一片,是常事。
当场怎么办别抽查,做全量统计。想清楚「如果有偏差,它会体现在哪个数上」,然后把那个数算出来(位置分布、长度比、词频、取值集合)。
怎么让它别再犯上校验脚本,并给一个总闸。总闸要能回答「不看内容能不能蒙对」这类问题,合格线用一个能解释来源的基准(如随机水平)。这条本身就是活案例,见 U03 第 4 节。

7参考给得很清楚,做出来还是不像

底下发生了什么「能跑」是它在优化的目标,「像那个参考」不是。中间缺了一次翻译:把视觉/风格拆成能被对照的具体数值。没拆,就只会回到分布中心。
当场怎么办停下来,先要一份映射表:参考里的项 / 实测值 / 落到哪 / 怎么判定。判定那一列写不出来的项,说明还没拆到位。
怎么让它别再犯定成流程:映射表先行 → 核心样本先做一个 → 人看一眼 → 再铺开 → 每轮跑回归对照。见 U05。

8说的是「小改」,做成了大工程

底下发生了什么模型对范围没有先验,「补全成一个完整方案」是高概率续写,而且做多了不会报错、只会显得更周到——没有反向压力。
当场怎么办把方案和原话并排:原话里出现的具体名词列一栏,方案里有、原话里没有的另列一栏。第二栏就是超出部分。
怎么让它别再犯把「动手前对着原话裁范围」定成开工的固定一步,而且超出部分不许自己批准,必须拿去问。见 U04 第 4 节。

9前提搞错了,后面全错但读起来很顺

底下发生了什么模型内部没有「我不确定」这个能中断生成的信号。概率分布再平坦也总有最大值,生成照样继续。
当场怎么办回到最开始,让它只用一句话复述前提(材料有几页、每页是什么、目标是什么),对完再往下。别让前提和结论混在一段里。
怎么让它别再犯把「确认前提」做成独立的一轮,放在任何分析之前。成本是几分钟,错了的代价是整条链。

10两个对话在版本控制上打架

底下发生了什么两个写者同时写同一个可写面。常见的面:工作树、暂存区(全仓库共享)、集成分支、共享配置文件、编号池(两边取到同一个号)。
当场怎么办按面判,不按身份判。先确认这个面此刻的写者是谁,另一方停手。提交时用显式路径,不要批量暂存。
怎么让它别再犯维护一份地盘表:有哪些面、各自当前的写者、哪些是共享面必须串行。交接要有明确时刻和明确一句话。见 U06。

11转发给另一个对话之后,信息走样了

底下发生了什么转述是一次生成,具体约束会被概括掉;而且接收方看不到这边的上下文,块里没写的东西它只能猜。
当场怎么办回到原话,把被概括掉的具体项补回去,重发一次。别在走样的基础上继续往下推。
怎么让它别再犯转发块三条硬规矩:不预填未拍板的决定、不代写提出者的原话、块要自足(背景与判据都在块里,不写「按上面说的」)。

12几个对话对同一件事说法不一致

底下发生了什么各自的上下文是各自攒的,没有共同的正本。三份各自可写的副本,必然长成三个样子,而且各自都很笃定。
当场怎么办别去「让它们对齐一下」——对齐一次就会漂一次。找出正确的那一份,以它为准。
怎么让它别再犯建一份只有一个写者的正本规则,其余全部只读。规则要改走那一个写者。

13越聊越笨,token 烧得飞快

底下发生了什么每一轮都要把整个上下文重读一遍——长对话里九成以上的花费买的是「把说过的话再读一遍」。同时,中段的内容注意力权重系统性偏低,早期说过的约束正落在那里。
当场怎么办问一句「这段内容下一个对话还需要吗」:需要 → 落成文件;只是本次过程 → 压缩;都用不上 → 开新对话。
怎么让它别再犯开工前排上下文预算:固定区(规则,放开头吃满缓存)/ 材料区(按需取片段,不整本贴)/ 工作区(放末尾),并留三成空白。见 U02。

14账单突然变贵,内容却没变多

底下发生了什么提示缓存按前缀匹配。开头只要改一个字,后面全部内容的缓存一次性失效,这一轮按全价重算。常见元凶:每轮在系统提示开头插时间戳、或频繁微调开场白。
当场怎么办检查最靠前的那段内容最近有没有改动。把会变的东西全部挪到末尾。
怎么让它别再犯固定顺序:长期不变的规则 → 本次固定材料 → 当前这一轮的问题。写定之后就别再动开头。

15某个终端在这台机上反复崩

底下发生了什么运行时层面的问题(进程创建失败、动态库初始化失败之类),和要跑的命令本身无关。重试同一个环境不会好转。
当场怎么办第一次失败就换另一个终端,别做第二次诊断。同一个运行时错误最多花一次工具调用去看。
怎么让它别再犯把「哪类活默认用哪个终端」写进规则文件,并写清「出现哪些错误字样时立刻换、不许重试」。例外是撞凭据/子进程的操作,换终端也躲不掉,那种才适用原样重试。

16给了在线链接,但打不开

底下发生了什么交付方默认「能生成链接就等于送达」,没有确认接收方的实际环境能不能访问。
当场怎么办要求改成本机文件,并给绝对路径。
怎么让它别再犯把「可视化产出一律落成本机文件 + 给绝对路径」写进规则文件,并在交付格式里固定这一项。

17它说任务在跑,其实早就停了

底下发生了什么「在跑」同样是一句被生成的话。进程可能已经退出、只剩一个壳,或者卡在某一步没有任何输出。
当场怎么办去看客观信号:进程列表、日志文件的最后写入时间、产物的修改时间。三者都不动就是停了。
怎么让它别再犯长任务一律要求周期性打点(每 N 步写一行带时间戳的进度),并且监控要同时覆盖失败信号,不能只等成功那一行——只等成功的话,崩了和还在跑长得一模一样。
补一条新的

格式固定:一个 h2 写症状(用第三人称陈述,不要写成对话),下面一张两列表,三行分别是底下发生了什么 / 当场怎么办 / 怎么让它别再犯。第三行必须写得出来才算一条完整的处方——写不出来,说明还没找到机制,只是记了一次救火。
