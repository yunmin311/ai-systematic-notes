特征工程与数据预处理

前五章都在讲"用什么模型、怎么评估"。但从业者有句老话:数据和特征决定了模型的上限,算法只是逼近这个上限。喂进去的特征是烂的,再强的模型也救不回——垃圾进,垃圾出。这一章讲喂模型之前那些决定成败的功夫:缺失值怎么补、文字类别怎么变数字、数值要不要缩放、怎么选出真正有用的特征。最后把它们打包成一个防数据泄露的流水线(呼应 D05)。学完它,Track A 经典机器学习就全通了,我手握做项目 P2 的全部工具。

4一句话本质

特征工程:把原始的、脏的、模型看不懂的数据,加工成干净的、模型吃得下的、信息量高的特征。这一步常常比"换个更高级的模型"带来的提升还大——因为模型只能从我喂的特征里学,喂不进去的信息它永远学不到。

为什么它是"性价比之王":换模型的提升往往是边际的(随机森林换成 XGBoost,可能就好一两个点),而一个好特征、或修好一处数据问题,可能让效果跳一大截。原始数据几乎从不是"开箱即用"的:有缺失(有人没填年龄)、有文字("北京/上海/广州"模型不认)、有量纲差异(收入几万、年龄几十,尺度差千倍)、有冗余和噪声。特征工程就是把这些一一收拾干净,再想办法把领域知识变成特征喂进去(比如"注册到首单的天数"往往比"注册日期"和"首单日期"分开更有用)。这活儿没有华丽公式,却最考功力、最见效——也最需要对数据和业务的理解。

7为什么特征工程最重要

一句业界共识:"垃圾进,垃圾出"。模型只是从特征里学规律的机器——我没喂进去的信息,它永远学不到;我喂了误导性的脏数据,它就学歪。所以在真实项目里,数据清洗 + 特征构造常常占掉大半时间,也带来大半提升。

一个直观对比:同样用随机森林,A 组直接把原始脏数据丢进去,B 组花两天补好缺失、编好类别、造了两个业务相关的新特征——B 组的效果往往甩开 A 组一大截,远超"把随机森林换成 XGBoost"那点提升。这不是说模型不重要,而是说特征是地基、模型是楼:地基不牢,楼盖多高都晃。对我这样从产品视角切入的人,这其实是好消息——特征工程拼的不是数学,而是对数据和业务的理解,这正是我的长处。接下来三节,是三类最常见、几乎每个项目都要做的清洗加工。

最常见的第一个脏问题:数据有窟窿。

8缺失值处理

真实数据总有缺失(没填的年龄、漏采的传感器读数)。多数模型不能直接吃带窟窿的数据,得先处理:要么删(删行或删列),要么填(用均值/中位数/众数,或用模型预测)。选哪种看"缺多少、为什么缺"。

判断的诀窍:删——某列缺了绝大部分(如 90% 是空),这列基本没信息,删列;某几行零星缺、且样本很多,删这几行也无妨。但别轻易删:删行会丢样本,某列缺失本身可能就是信号(比如"没填收入"的人可能有共性)。填(imputation)——数值列常用中位数(比均值抗离群点),类别列用众数(最常见的那个),讲究的用其它特征预测缺失值。还有个实用技巧:填的同时加一列"这里原本是不是缺的"(缺失标记),把"缺失"这个信息也保留给模型。关键纪律:填充用的统计量(如中位数)必须只从训练集算,再套用到验证/测试——否则就是 D05 说的数据泄露(第 12 节的流水线自动帮我守住这条)。

第二个:模型只认数字,但很多特征是文字。

9类别编码

模型只吃数字,可"城市=北京/上海/广州""颜色=红/黄/蓝"是文字。得编码成数字。最常用 one-hot(独热)编码:每个类别拆成一列 0/1。切忌简单编成 1/2/3——那会凭空给类别强加"大小顺序",误导模型。

为什么不能编成 1/2/3:如果把 红=1、黄=2、蓝=3,模型会以为"蓝 > 黄 > 红"、甚至"红+蓝的平均=黄",可颜色之间根本没有这种大小关系,这是无中生有的误导。one-hot 解决它:红黄蓝变成三列 是否红/是否黄/是否蓝,每个样本在对应列填 1、其余填 0——彼此平等、没有强加顺序。例外:如果类别本身有序(如"小/中/大""差/中/好"),编成 1/2/3(序数编码)反而合理,因为顺序是真实的。注意:类别特别多时(几千个城市),one-hot 会炸出几千列,这时改用其它编码(如目标编码/频数编码)。树模型(D03)对类别编码更宽容,线性/神经网络更依赖 one-hot。

第三个:数值特征的量纲差太多。

10数值缩放

不同数值特征常量纲悬殊:月收入几万、年龄几十——差上千倍。对靠距离/权重的模型(线性回归、逻辑回归、KNN、神经网络),大数值特征会盖过小的,得缩放到同一尺度(标准化或归一化)。树模型不用——它按特征逐个切,不在乎尺度(D03)。

两种常见缩放:标准化(减均值、除标准差,变成"均值 0、标准差 1")最常用,适合大多数场景;归一化(压到 0~1 区间)在需要固定范围时用。为什么重要:靠距离的模型里,"收入差 1000 元"和"年龄差 1000 岁"在数值上一样大,但后者荒谬——不缩放的话,模型会被大数值特征绑架,几乎忽略小数值特征。缩放后大家站在同一起跑线,模型才公平地看待每个特征;梯度下降(D01)也会收敛得更快更稳。务必记住:缩放的均值/标准差只能从训练集算,再套到测试集——又是数据泄露的高发区,交给流水线来守。

收拾干净之后:留哪些特征、怎么造新的、怎么安全地串起来。

11特征选择、构造与流水线

选择:去掉没用/冗余的特征(它们只添噪声、拖慢模型、还助长过拟合)——少而精。构造:用领域知识造出信息量更高的新特征(把两列组合、把连续值分箱)。流水线:把"预处理 + 模型"打包成一个整体,让预处理只在训练集上拟合——从机制上杜绝数据泄露(D05)。

选择的直觉:不是特征越多越好。冗余特征(如"身高厘米"和"身高米")、无关特征只会稀释信号、增加过拟合风险;可以看特征重要性(D03)、相关性来砍。构造是最能体现功力的一环:模型学不会的关系,我可以手动喂给它——例如把"注册日期"和"首单日期"相减,造出"决策天数"这个强特征;把连续的年龄分箱成"少年/青年/中年/老年"有时更稳。流水线(Pipeline)是工程上的定海神针:它把填充、编码、缩放、模型串成一条链,fit 时全部只学训练集的统计量,predict 时原样套用——我再也不会手滑在划分前就标准化全量数据(D05 的经典泄露)。先清洗、再选择、边构造,全程装进流水线——这就是专业的数据准备姿势。

把这一整套——填充、编码、缩放、模型——用一条流水线安全地串起来。

12组装:一条防泄露的预处理流水线

scikit-learn 的 Pipeline + ColumnTransformer 是专业做法:数值列走"填充+缩放",类别列走"填充+one-hot",再接模型,整条一起 fit——泄露无处发生:

preprocess_pipeline.pypython
from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.ensemble import RandomForestClassifier

num_cols = ["age", "income"]        # 数值列
cat_cols = ["city", "gender"]       # 类别列

# ② 数值:中位数填充 → ④ 标准化
num_pipe = Pipeline([("impute", SimpleImputer(strategy="median")),
                     ("scale",  StandardScaler())])
# ② 类别:众数填充 → ⑨ one-hot
cat_pipe = Pipeline([("impute", SimpleImputer(strategy="most_frequent")),
                     ("onehot", OneHotEncoder(handle_unknown="ignore"))])

pre = ColumnTransformer([("num", num_pipe, num_cols),      # 各列走各自的处理
                         ("cat", cat_pipe, cat_cols)])

# ⑪ 把「预处理 + 模型」打包成一条链
model = Pipeline([("prep", pre),
                  ("clf",  RandomForestClassifier(random_state=0))])

model.fit(X_train, y_train)         # 预处理只在训练集上拟合 → 天然防泄露(D05)
print(model.score(X_test, y_test))  # 测试时自动套用同一套变换

逐块对照:数值列用中位数填(②)+ 标准化(④);类别列用众数填(②)+ one-hot(⑨);ColumnTransformer 让不同列走不同处理;最外层 Pipeline 把整套预处理和模型捆成一个对象。最关键的是:model.fit(X_train, ...) 时,填充的中位数、缩放的均值、one-hot 的类别全部只从训练集学;model.score(X_test, ...) 时原样套用——我从机制上不可能再犯"划分前标准化全量数据"的泄露错误(D05)。这也让整套东西能干净地进 D05 的交叉验证和网格搜索。这就是专业项目里数据准备的标准姿势。

15自测 · 思考题

  1. 一句话本质。为什么特征常比模型更决定结果?
    参考答案

    模型只能从我喂的特征里学,喂不进去的信息学不到("垃圾进垃圾出");修数据/造特征的提升常大于换模型。

  2. 编码。为什么不能把无序类别编成 1/2/3?
    参考答案

    会强加不存在的大小/顺序关系(蓝>黄>红),误导模型。要用 one-hot 让各类平等;有序类别才用 1/2/3。

  3. 缩放。哪些模型需要缩放、哪些不用?
    参考答案

    靠距离/权重的(线性、逻辑、KNN、神经网络)需要;树模型不用,它按特征逐个切、不受量纲影响。

  4. 流水线。Pipeline 怎么防数据泄露?
    参考答案

    把预处理和模型打包,fit 时统计量(中位数/均值/类别)只从训练集学,predict 时套用——不可能在划分前污染全量。
