PyTorch 与完整训练循环

还记得 D01 那个手写的训练循环吗——亲手算损失、亲手调那 1 个参数。第 7 章又讲了神经网络怎么前向、怎么反向传播。但真要训练一个有几万、几百万参数的网络,靠手写每一层的导数是不可能的。PyTorch 就是来解决这件事的:它把"数组运算 + 自动求导 + 数据加载 + 训练循环"这套骨架标准化了,让人只管"搭什么网络",把"怎么算梯度"完全交给框架。这一章把 D01 那个玩具循环,升级成真正的深度学习训练循环——后面 Track B 每一章(CNN、序列模型、迁移学习)都在这个循环里跑。

图解骨架约 30 分钟,动手 + 精读约 4~6 小时。跟着敲一遍那个五步循环,就握住了整个深度学习的"发动机"。

这一章要立起来的骨架

  • 为什么要框架——手写反向传播不现实,框架自动求导 + GPU 加速 + 现成组件
  • 张量 Tensor——像 NumPy 数组,但能上 GPU、且会记录运算以便求导
  • 自动求导 autograd——只写前向,一句 loss.backward() 框架把所有梯度算好
  • 数据管道 Dataset / DataLoader——把数据切成小批量、打乱、按需喂
  • 训练循环五步——前向 → 算损失 → 梯度清零 → 反向 → 更新,背下来

4一句话本质

PyTorch:一个"会自己算梯度的 NumPy"。使用者只负责写"数据怎么前向流成损失",框架负责把"每个参数该往哪调"(梯度)自动算好;再配上现成的层、优化器和数据管道,训练一个网络就浓缩成一个固定的五步循环。

为什么这是革命性的:D01 里模型只有 1 个参数,能手推它的导数;可一个真实网络有几百万个参数、几十层非线性变换,手推每个参数的导数是天方夜谭。PyTorch 用自动求导把这件最难的事变成一行代码。剩下的——把数组搬上 GPU 加速、把常用的层(线性层、卷积层)做成现成积木、把数据切批打乱——也都封装好了。于是注意力可以完全放在"搭什么样的网络、解决什么问题"上,而不是"梯度怎么算"。PyTorch 和另一个框架 TensorFlow 是业界两大主流,近几年研究和教学几乎都用 PyTorch,本课程也用它。

7为什么要框架

手写一个多层网络的反向传播,等于手推几百万个参数的导数——不现实、也极易出错。框架的头号价值就是:只写"前向怎么算",它自动把"每个参数的梯度"算好。再加上 GPU 加速和现成的层/优化器,训练网络才从"科研苦力"变成"搭积木"。

具体省了三件事:一、自动求导。这是核心——D01 里能手推 1 个参数的导数,但深层网络里,损失对第一层某个参数的导数要沿着几十层链式法则一路传回来,人工推导既慢又必错。框架把这一步自动化(第 9 节)。二、GPU 加速。神经网络的运算本质是海量矩阵乘法,GPU 天生擅长并行做这个,能比 CPU 快几十上百倍;框架让人一句 .to("cuda") 就把数据和模型搬上 GPU,代码几乎不用改。三、现成组件。线性层、卷积层、各种激活函数、各种优化器(Adam、SGD)都是封装好的积木,import 进来就用,不用重造轮子。这三件事凑齐,才能把精力放在"设计网络、解决问题"上。

框架里一切数据的载体,先认识它:张量。

8张量 Tensor

张量就是 PyTorch 版的 NumPy 数组(第 3 章):同样是带形状的多维数字网格,索引、切片、广播几乎一模一样。但它多两样本事:能搬到 GPU 上算,以及能记录自己经历过哪些运算,好让框架回头求导。

可以先粗暴地把"张量"理解成"能上 GPU、还会记账的 NumPy 数组"——第 3 章练过的形状意识(几行几列、哪个轴)在这里原样管用。两个新东西:设备(device)——张量住在 CPU 还是 GPU 上,用 .to("cuda") 搬家,模型和数据必须住在同一个设备上才能算。数据类型(dtype)——神经网络的输入几乎都用 float32(32 位小数),因为要做小数运算和求导;整数标签用 int64。一个新手最常见的报错就是 dtype 或 device 对不上,记住"输入转 float、模型和数据同设备"能躲开一大半。下面这段展示张量和它的求导能力:

tensor_basics.pypython
import torch

# 张量:和 NumPy 数组几乎一样,能索引、切片、广播
a = torch.tensor([[1.0, 2.0], [3.0, 4.0]])   # 2 行 2 列,dtype 默认 float32
print(a.shape)          # torch.Size([2, 2])——形状意识和第 3 章一致
print(a * 2)            # 逐元素运算,广播规则同 NumPy

# requires_grad=True:告诉框架"请记录对这个张量的运算,我要对它求导"
x = torch.tensor(2.0, requires_grad=True)
y = x ** 2 + 3 * x      # 前向:随便算一个式子
y.backward()            # 反向:一句话,自动求导
print(x.grad)           # dy/dx = 2x + 3 = 7.0 —— 框架已经算好了

上面那句 y.backward() 是全章的心脏,单拎出来讲。

9自动求导 autograd

写前向计算时,PyTorch 在背后悄悄记下每一步运算,连成一张"计算图"。当对最终的损失调用 loss.backward(),它就沿这张图从后往前用链式法则,一路把"损失对每个参数的梯度"算出来,存进各参数的 .grad 里。这正是第 7 章"反向传播"的自动化版本。

拆开看:前向时,数据 x 经过模型算出预测 ŷ,再和真值算出损失 loss——这一串运算被框架记成一张从参数指向 loss 的图。loss.backward() 做的,就是第 7 章讲的反向传播:从 loss 出发,反着这张图逐层套链式法则,得到"每个参数改变一点点、loss 会变多少",也就是梯度。完全不用知道每层导数长什么样——写好前向,梯度就是免费的。有个坑要记住:梯度是累加进 .grad 的(为某些高级用法方便),所以每轮训练前必须先 zero_grad() 清零,否则这轮的梯度会和上轮的叠在一起、把方向带偏(第 11 节那五步里的第③步就是干这个)。

有了会求导的模型,还得有源源不断、切好批的数据喂它。

10数据管道 Dataset / DataLoader

Dataset 定义"一条样本长什么样、怎么取第 i 条";DataLoader 把 Dataset 包起来,负责切成小批量(mini-batch)、每轮打乱、并行加载,一批一批地喂给训练循环。为什么切批:一次喂全部数据太占内存、也更新太慢;一次只喂一条又太抖——小批量(常见 32/64/128)是这两者的平衡(呼应第 6 章的 mini-batch)。

直觉:训练不是把全部数据连续塞进模型,而是像"一勺一勺喂"——每一勺(一个 batch)算一次前向反向、更新一次参数。DataLoader 就是那个自动盛勺的人:告诉它"每勺 32 条、每轮开饭前先把菜打乱",它就在循环里不断递过来 (xb, yb)。打乱(shuffle)很重要:如果数据原本按类别排好序(先全是猫、后全是狗),不打乱的话模型会先被猫带偏、再被狗带偏,学得不稳;打乱让每一批都是杂样本,梯度方向更可靠。对自己的数据,只要把它整理成"能按下标取第 i 条"的 Dataset,DataLoader 就能直接用——第 12 节的例子用最简单的 TensorDataset(直接把两个张量配成对)。

五个零件到齐,把它们拼成那个每轮都跑的循环——本章的落点。

11训练循环五步(背下来)

深度学习的训练,剥到底就是一个固定的五步循环,一轮一轮地重复:①前向算预测 → ②算损失比对真值 → ③梯度清零 → ④反向求梯度 → ⑤更新参数。Track B 后面所有模型都在这个循环里跑,变的只是"模型"和"数据",循环骨架一字不改。

逐步说清"为什么缺不得":①前向——把这一批数据喂进模型,得到预测,这是"当前参数下模型的答案"。②算损失——用损失函数量出"预测离真值多远",这是要压小的目标(第 6 章)。③梯度清零 zero_grad——上一轮的梯度还赖在 .grad 里(autograd 是累加的,第 9 节),不清零就会和这轮叠加、方向出错;新手最常忘这步,忘了模型就学不动或乱跳。④反向 backward——一句话触发自动求导,把这批数据下"损失对每个参数的梯度"算好。⑤更新 step——优化器(如 Adam)按梯度把每个参数往"损失下降"的方向挪一小步(步长由学习率定,第 6 章)。这五步跑完是一次更新;把所有批跑一遍叫一个 epoch(轮次),通常要跑几十上百个 epoch,损失才降到位。

把五个零件拼成一段能跑的完整代码——这就是以后所有训练脚本的模板。

12组装:一段完整的训练脚本

下面这段就是深度学习训练的"标准模板":数据 → 管道 → 模型 → 损失/优化器 → 五步循环。记住它的形状,以后换任何模型都是往里填空:

train_loop.pypython
import torch
import torch.nn as nn
from torch.utils.data import TensorDataset, DataLoader

# 1. 数据 → 张量 → 小批量管道(第 10 节)
X = torch.randn(500, 4)                    # 500 个样本,每个 4 个特征(float32)
y = torch.randn(500, 1)                    # 对应的目标值
loader = DataLoader(TensorDataset(X, y),   # 把 (X, y) 配成可取第 i 条的数据集
                    batch_size=32,         # 每批 32 条
                    shuffle=True)          # 每个 epoch 打乱

# 2. 模型:现成积木堆起来(线性 → 激活 → 线性),第 7 节
model = nn.Sequential(
    nn.Linear(4, 16),                      # 4 个输入 → 16 个隐藏单元
    nn.ReLU(),                             # 激活函数(第 7 章)
    nn.Linear(16, 1),                      # 16 → 1 个输出
)

# 3. 损失函数 + 优化器(第 6 章)
loss_fn = nn.MSELoss()                                     # 均方误差(回归)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)  # Adam,学习率 0.001

# 4. 训练循环:牢记这五步(第 11 节)
for epoch in range(100):                   # 跑 100 个 epoch
    for xb, yb in loader:                  # DataLoader 一批一批喂
        pred = model(xb)                   # ① 前向:算预测
        loss = loss_fn(pred, yb)           # ② 算损失
        optimizer.zero_grad()              # ③ 梯度清零(别忘!第 9 节)
        loss.backward()                    # ④ 反向:autograd 自动求梯度
        optimizer.step()                   # ⑤ 更新:按梯度挪一小步
    if epoch % 20 == 0:
        print(f"epoch {epoch:3d}  loss {loss.item():.4f}")

逐块对照 D01:D01 里手写 loss = (y - w*x)**2、手推梯度、手动 w -= lr * grad;这里 nn.MSELoss() 算损失、loss.backward() 求所有参数的梯度、optimizer.step() 更新——三步各自被一行代码接管,循环的骨架却和 D01 一模一样。把 nn.Sequential(...) 换成一个 CNN,这段代码其它部分一字不改,就是 D08 的手写数字识别。这就是为什么说"五步循环是 Track B 的底盘"。

进阶挑战 · 上手练习

把它真的跑起来

①按第 6 节装好 PyTorch(CPU 版即可),把上面这段原样跑通,观察 loss 一路下降。②故意删掉 optimizer.zero_grad() 那一行,再跑——看 loss 变得多离谱,亲身体会"梯度不清零"的后果。③把学习率 lr=1e-3 改成 1.0,看 loss 如何震荡/发散(呼应第 6 章学习率)。④把模型中间的 16 改大到 128,看参数变多后训练有什么不同。跑通这四步,就真正握住了训练循环。

用 PyTorch 得先学会手推反向传播正相反——框架就是自动求导,只需写前向。反向传播的道理(第 7 章)懂即可。
没有 GPU 就学不了深度学习CPU 就能学完本章和小项目(如 P3)。GPU 只是让大模型训练更快,不是入门门槛。
zero_grad() 可有可无不可无。梯度是累加的,不清零会把上一轮的梯度叠进来,方向出错、训练失败。
张量就是 NumPy 数组,没区别用法几乎一样,但张量能上 GPU、能自动求导——这两点正是深度学习需要的。
一个 epoch 就是一次参数更新一个 epoch 是"全部数据过一遍";每个 batch 更新一次,一个 epoch 里更新很多次。

15自测 · 思考题

  1. 框架的头号价值。PyTorch 省掉的最要命的一件事是什么?
    参考答案

    自动求导:只写前向计算,loss.backward() 就把损失对所有参数的梯度自动算好,免去手推深层网络导数这件不可能的苦差。

  2. 五步顺序。不看资料,写出训练循环那五步,并说清③为什么不能省。
    参考答案

    ①前向 pred=model(x) → ②算损失 → ③梯度清零 zero_grad → ④反向 backward → ⑤更新 step。③不能省:梯度是累加进 .grad 的,不清零就会叠上一轮的梯度,方向出错。

  3. 张量 vs 数组。张量比 NumPy 数组多了哪两样本事?
    参考答案

    ①能搬到 GPU 上并行加速;②能记录运算、支持自动求导(requires_grad)。日常的形状/索引/广播用法则和 NumPy 基本一致。

  4. 为什么切小批量。DataLoader 为什么要把数据切成 mini-batch、还要 shuffle?
    参考答案

    切批:整批太占内存、更新太慢,单条太抖,小批量(32/64)是平衡。shuffle:防止数据原有顺序(如先猫后狗)把训练带偏,让每批都是杂样本、梯度更可靠。
