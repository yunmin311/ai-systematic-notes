优化器、正则化与训练技巧

前几章我有了模型(CNN、RNN)和训练循环(D07)。但真训练起来,我会撞上两件糟心事:要么训不动(损失半天不降、震荡、卡住),要么过拟合(训练集上分数漂亮,一到没见过的新数据就拉胯)。这一章是把模型训好的一套手艺——更聪明的下坡方法(优化器)、防死记硬背的手段(正则化)、让训练更稳的归一化、以及调学习率的节奏。它们不改变模型结构,却常常决定我能不能真正训出一个好模型。

图解骨架约 30 分钟,精读 + 调参约 4~6 小时。这一章是"实战补丁包":每个技巧都对应一个真实痛点,记住"什么时候该用哪一个"比背定义更重要。

读完这一章,我脑子里会立起来的骨架

  • 训练的两大敌人——训不动(欠拟合/不收敛) vs 过拟合(记住了训练集)
  • 优化器——从 SGD 到 Adam:怎么更聪明、更稳地往损失低处走
  • 正则化——Dropout、权重衰减、早停、数据增强:专治过拟合
  • 归一化——BatchNorm:让每层输入更规整,训练更快更稳
  • 学习率调度 + 训练诊断——按节奏调步长;看训练/验证曲线对症下药
从哪来 · 到哪去

接前面:优化器续 第 6 章的梯度下降/学习率;过拟合与验证续 D05;这些技巧插进 D07 的五步循环。通向后面:正则化、学习率调度到了训练大模型(Track C)照样是核心手艺,只是规模更大。

4一句话本质

这一章的所有技巧,都在解决两个问题之一:①怎么更快更稳地把损失降下去(优化器、归一化、学习率调度),②怎么让降下去的模型别只是"背下了训练集",还能应对新数据(正则化)。它们不动模型结构,却常常是"能训出好模型"和"训了个废物"的分水岭。

为什么需要一整套手艺:深度网络的损失面又高维又崎岖,朴素的梯度下降容易走得又慢又晃(甚至卡在坏地方);而参数一多,模型又极其擅长"死记硬背"训练集、对新数据却一无所知(过拟合,D05)。所以实战里,搭好模型只是开始,真正吃功夫的是调:换个聪明的优化器让它下坡稳、加正则化逼它学"规律"而不是"背答案"、用归一化让每层数据别乱、按节奏调学习率。好消息是——这些技巧在 PyTorch 里几乎都是"一行代码开启",难的不是用,而是判断此刻该用哪个。这一章就教我这个判断。

7训练的两大敌人:看曲线诊断

训练时同时盯两条损失曲线——训练损失和验证损失(D05)。两条都高、降不动 = 欠拟合/没训好(模型太弱或没训够);训练损失一路降、验证损失却掉头往上 = 过拟合(开始死记硬背训练集);两条都低且贴近 = 刚好。看懂这张图,我才知道该拧哪个旋钮。

诊断决定用药:欠拟合(训练损失都降不下去)——问题在"训得动"这一侧:模型太小?学习率不对?训练轮数不够?该加大模型、调优化器/学习率、多训。过拟合(训练好、验证差,两条曲线岔开越来越大)——问题在"泛化"这一侧:该上正则化(第 9 节)、或早点停(第 9 节的早停)、或加更多/更多样的数据。图 2 画出了过拟合的典型样子,以及"早停"该停在哪。

对付"训不动",先换一个更聪明的下坡方法:优化器。

8优化器:从 SGD 到 Adam

优化器决定"拿到梯度后,参数具体怎么挪"。最朴素的 SGD 就是 第 6 章的"顺着梯度走一步"。改良版加了两样聪明:动量(顺着惯性冲,少震荡、过小坑)和自适应学习率(每个参数按自己的情况调步长)。集大成者是 Adam——两样都占,鲁棒好用,默认先用它。

直觉:朴素 SGD 像一个没有惯性的球,梯度指哪走哪,遇到崎岖损失面容易左右横跳、走得慢。动量(Momentum)给它加了惯性——像真的球滚下山,会累积方向、冲过小坑小坎,更快更稳到谷底。自适应学习率(如 Adam 里的机制)则给每个参数配一个"个性化步长":常更新的参数步子小一点、少更新的大一点,省去手动为不同参数调学习率的苦。Adam 把动量和自适应合在一起,对超参数不那么敏感、开箱即用,是绝大多数场景的默认选择(torch.optim.Adam)。什么时候不用 Adam?一些追求极致泛化的视觉任务里,精调过的 SGD + 动量有时能到更好的最终精度——但那是进阶调参,入门和多数项目,先 Adam,学习率从 1e-3 起。

对付"过拟合",祭出正则化四件套。

9正则化:专治过拟合

正则化 = 一切"故意给模型添点约束/干扰,逼它别死记硬背、去学真规律"的手段。四件常用套装:Dropout(训练时随机关掉一部分神经元)、权重衰减(惩罚过大的权重,让模型更简单)、早停(验证损失回升就停)、数据增强(对训练数据做随机变换,变相扩充数据)。

逐个说治什么病:Dropout——训练时每一步随机"关掉"一部分神经元(如 20%),逼网络别过度依赖某几个神经元、学出更鲁棒的冗余表示;测试时全开。一行 nn.Dropout(0.2)。权重衰减(weight decay,即 L2 正则)——在损失里加一项"惩罚过大的权重",鼓励模型用更小、更平滑的权重,通常更不容易过拟合;在优化器里设 weight_decay=1e-4 即可。早停(early stopping)——盯着验证损失,一旦它连续几轮不再下降(甚至回升,图 2),就停止训练、保留验证最好的那版权重,简单又有效。数据增强(data augmentation)——对训练图像做随机裁剪、翻转、微调亮度等,让模型见到更多"变体",相当于免费扩充数据,是视觉任务里性价比极高的一招。用法口诀:先有过拟合迹象,再加正则;从早停 + 适度 Dropout/权重衰减起手,数据增强(图像)几乎必配。

再补两块让训练更稳、更有节奏的技巧:归一化和学习率调度。

10归一化与学习率调度

批归一化(BatchNorm):在网络中间,把每一层的输入按批"拉回均值 0、方差 1"再往下传——让每层拿到的数据分布稳定,训练更快更稳、还能配更大的学习率(呼应 D06 的特征缩放,只是搬到了网络内部)。学习率调度:训练过程中动态调学习率——常见"先小步热身(warmup)、中途大步、后期逐渐减小",让模型先站稳、再快走、最后精修。

为什么 BatchNorm 有用:D06 讲过输入特征要缩放,否则量纲乱、梯度下降走得歪。可深层网络里,数据经过几层变换后,中间层拿到的分布又乱了。BatchNorm 就在中间每层前把数据重新规整一遍,梯度更好走、训练明显更快更稳,也让网络对学习率没那么挑剔——用 nn.BatchNorm2d/1d 一行加上。学习率调度解决的是"一个固定步长走全程不够好":开头参数很乱,步子太大容易冲飞,先热身用小学习率站稳;中段大步快速下坡;接近谷底再把步子减小精修,别在最低点附近反复横跳(呼应 第 6 章学习率)。PyTorch 的 torch.optim.lr_scheduler 提供各种现成调度器,训练大模型时几乎必用。

把这些技巧一次性装到 D07 的循环上,看它长什么样。

11组装:带全套技巧的训练循环

下面在 D07 五步循环的基础上,加上 Adam + 权重衰减 + Dropout(在模型里)+ 学习率调度 + 早停。看清楚:循环骨架没变,技巧都是"挂"上去的:

train_with_tricks.pypython
import torch
import torch.nn as nn

# 模型里加 Dropout(正则化)+ BatchNorm(归一化)
model = nn.Sequential(
    nn.Linear(784, 256), nn.BatchNorm1d(256), nn.ReLU(), nn.Dropout(0.2),
    nn.Linear(256, 10),
)

loss_fn = nn.CrossEntropyLoss()
# Adam(聪明的优化器)+ weight_decay(权重衰减=L2 正则)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-4)
# 学习率调度:每 10 个 epoch 把学习率乘 0.5(后期精修)
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=10, gamma=0.5)

best_val, patience, wait = 1e9, 5, 0          # 早停用
for epoch in range(100):
    model.train()                              # 训练模式:Dropout/BN 生效
    for xb, yb in train_loader:
        pred = model(xb)                       # ① 前向
        loss = loss_fn(pred, yb)               # ② 算损失
        optimizer.zero_grad()                  # ③ 清零
        loss.backward()                        # ④ 反向
        optimizer.step()                       # ⑤ 更新
    scheduler.step()                           # 每轮末:按调度调学习率

    model.eval()                               # 评估模式:Dropout 关、BN 用统计量
    val = evaluate(model, val_loader)          # 在验证集上算损失(D05)
    if val = patience:
            print(f"早停于 epoch {epoch}"); break

逐块对照:nn.Dropout/nn.BatchNorm1d 加在模型里;Adam(..., weight_decay=) 一次给了聪明优化器 + 权重衰减;StepLR 是学习率调度;最后那段 best_val/wait 是早停——验证损失连续 5 轮不再变好就停、并保留最好那版。特别注意 model.train() 和 model.eval() 的切换:训练时 Dropout 要随机丢、BatchNorm 用当前批的统计;评估时 Dropout 全开、BatchNorm 用训练期累计的统计——忘了切 eval 是新手常见的"测试结果诡异"根源。五步循环本身,还是 D07 那五步。

14自测 · 思考题

  1. 看曲线诊断。训练损失一直降、验证损失掉头上升,是什么问题?怎么办?
    参考答案

    过拟合。对策:加正则化(Dropout/权重衰减/数据增强)、早停、或加更多数据;而不是继续训。

  2. 优化器。Adam 比朴素 SGD 聪明在哪?
    参考答案

    两点:动量(累积方向、少震荡、过小坑)+ 自适应学习率(每个参数按情况调步长)。默认好用、对超参不敏感。

  3. 正则化选型。说出三种正则化手段及各自做法。
    参考答案

    Dropout(训练随机关神经元)、权重衰减(惩罚大权重)、早停(验证回升就停)、数据增强(随机变换训练数据)——任答三。

  4. train/eval。为什么评估前一定要 model.eval()?
    参考答案

    训练模式下 Dropout 会随机丢、BatchNorm 用当前批统计;评估要 Dropout 全开、BN 用累计统计。不切换会得到诡异/不稳定的测试结果。
