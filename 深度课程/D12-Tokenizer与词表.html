Tokenizer 与词表

至此站到了大模型的门里。Track C 要做的事,是把 第 8 章那张鸟瞰图的每一站拆到底——而第一站,就是文字进入模型前的最后一道关卡:分词(Tokenizer)。模型不认字,只认数字。所以任何一句话进来,都要先被切成一个个 Token(词块)、再换成编号。这一步看着琐碎,却决定了三件天天遇到的事:为什么中文更费钱、为什么模型数不清一个词里有几个字母、为什么上下文窗口的"长度"是按 Token 算的。

图解骨架约 25 分钟,动手 + 精读约 2~3 小时。本章配套的动手方式:打开在线 Tokenizer,把句子切开对照观察。

这一章要立起来的骨架

  • 为什么要分词——模型只吃数字,文字必须先切块再编号
  • 切多大才对——按字太碎、按词表爆炸,子词(subword)是折中
  • BPE 怎么切——从字符起步,把最常一起出现的一对反复合并
  • 词表 vocabulary——切出来的块和编号的对照表,大小是关键取舍
  • 后果——中文更费 token、模型数不清字母、按 token 计费与计长度

4一句话本质

Tokenizer:一本"文字↔编号"的对照词典,外加一套把任意文字切成词典里条目的规则。它把人类的字符串,翻译成模型唯一能处理的东西——一串整数。模型眼里从来没有"字",只有这些编号。

为什么必须有这一步:神经网络的输入是数字张量(D07),它没法直接吃"今天天气真好"这串字符。于是需要一个约定:把文字切成有限种类的小块,每种块分配一个固定编号。这本"词典"叫词表(vocabulary),切的规则叫 Tokenizer(分词器)。它是在训练模型之前就定好、之后再也不能改的——因为模型的每个编号都对应着训练时学到的一个向量,换词表等于把模型的字典抽走。所以 Tokenizer 是模型的"出生设置",也是它能力和成本的一道硬边界。

先说清最根本的那件事:模型为什么读不了字。

7为什么要分词

神经网络只做数字运算(D07 的张量),它没有"认字"这个能力。所以必须先约定一本有限的词典:把文字切成词典里的条目,每条给一个编号。"有限"是关键——模型的输出层要为词典里每一个条目算一个概率(D02 的 softmax),词典无限大就没法算。

顺着走一遍:输入"今天天气真好"→ Tokenizer 按规则切成若干块(比如「今天」「天气」「真」「好」)→ 查词表得到编号(比如 [3245, 8721, 522, 1043])→ 这串整数才是模型真正的输入。模型算完,输出的也是"词表里每个条目作为下一个 Token 的概率"(第 8 章的第 ⑤ 站),抽一个编号,再用同一本词表翻回文字。所以词表既是入口也是出口:模型能说出的一切,都是这本词典里条目的排列组合——它无法输出词典里没有的东西(生僻字通常被拆成几个字节块拼出来)。

既然要切,那切多大?这是个有代价的选择。

8切多大才对:字 / 词 / 子词

三种粒度各有毛病:按字符切——词表极小,但一句话变超长、每个字符几乎没含义;按完整单词切——含义足,但词表要几十上百万还总遇到没见过的新词;按子词(subword)切——把常见词整块保留、把罕见词拆成常见片段,兼顾两头。今天所有主流大模型都用子词。

为什么子词是赢家:语言里少数词极常用、多数词很罕见。子词的策略是"常用的整块留着,罕见的拆开拼"——比如 unhappiness 可能被切成 un+happi+ness,三块都是常见片段。好处有三:①词表能压在几万这个可控规模;②永远不会遇到"不认识的词"(实在不行就拆到字符/字节级,总能拼出来);③还顺带保留了构词法的信息(un- 这个前缀在很多词里都出现,模型能学到它表否定)。代价是:一个词可能被切成好几块,模型看到的"最小单位"不是人眼里的字或词——这正是第 10 节那些怪现象的根源。

子词的切法从哪来?不是人定的,是从语料里"统计"出来的。

9BPE:把最常一起出现的一对反复合并

BPE(Byte Pair Encoding,字节对编码)是最主流的子词算法。思路极朴素:先把所有文字拆成单个字符,然后统计"哪两个相邻块最常一起出现",把这一对合并成一个新块;重复几万次,直到词表达到设定大小。常用的组合自然就被合并成了整块,罕见的仍是碎片。

举个缩小版例子:语料里有大量 low、lower、lowest。一开始全是字符 l o w e r s t;统计发现 l+o 最常挨着 → 合并成 lo;下一轮 lo+w 最常挨着 → 合并成 low;再下一轮可能把 e+r 合成 er……几轮之后,low 和 er 都成了词表里的整块,于是 lower 只需两个 Token。这个"合并顺序表"就是训练出来的 Tokenizer,以后切任何新文本,都照这张表从头合并一遍。注意两点:①它纯靠统计,不懂语义——切出来的块未必符合语言学上的词根;②它在字节层面兜底(所以叫 Byte Pair),意味着任何字符——罕见汉字、emoji、乱码——都能被拼出来,永不失败。

切法定了,那本"词典"本身有多大?这个数字牵一发动全身。

10词表大小,与三个真实后果

词表(vocabulary)= 所有 Token 与编号的对照表,现代模型通常几万到二十几万条。词表大:同样文本切出的 Token 更少(省钱省长度),但模型输出层更宽、更吃显存;词表小:反过来。这个取舍再加上"训练语料以英文为主"这个事实,直接造成天天遇到的三个现象。

后果一:中文更费 token。英文的常见词在 BPE 里往往合成了整块(the、ing 各 1 个 Token),而中文语料在训练时占比小、常用组合被合并得少,很多汉字甚至要 1~2 个 Token 才能表示。结果:同样意思的一段话,中文的 Token 数常常是英文的1.5~2 倍——而 API 按 Token 计费、上下文窗口按 Token 计长度,所以中文更贵、也更快撑满窗口。后果二:模型数不清字母。问它 "strawberry 里有几个 r",它眼里根本不是 s-t-r-a-w... 这些字母,而是 straw+berry 两个整块——它从没"看见"过单个字母,自然数不准。后果三:一切以 Token 为单位。计费、上下文窗口上限、生成速度,统统按 Token 算,不是按字数——这就是为什么要对"Token"这个词有肌肉记忆(D17 会算这笔账)。

用几行代码亲手切一遍,把上面的话变成自己的观察。

11组装:亲手切一段中英文对比

用 OpenAI 的 tiktoken 库(装一行 pip install tiktoken)可以在本地看到真实的切分结果。跑一遍,会亲眼看到中英文的 Token 数差距:

tokenize_demo.pypython
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")   # 一种常用词表(约 10 万条)

def show(text):
    ids = enc.encode(text)                    # 文字 → 编号列表(这就是模型的输入)
    pieces = [enc.decode([i]) for i in ids]   # 把每个编号翻回它对应的那一块
    print(f"{len(ids):3d} tokens | {text}")
    print("        切成:", pieces)

show("Machine learning is fun.")             # 英文
show("机器学习很有意思。")                      # 同样意思的中文
show("strawberry")                           # 看看它被切成哪几块
show("🍓 emoji 也能切")                       # 字节兜底:什么都切得动

会观察到三件事,正好印证第 10 节:①中文那句的 Token 数明显多于英文;②strawberry 被切成 straw+berry 之类的整块——模型确实"看不见"单个字母;③emoji 和任何生僻符号都能被切出来(字节兜底),永远不会失败。把自己常写的提示词丢进去切一次,对"这段提示词有多贵"就有了实感。

进阶挑战 · 亲手验证

把三个后果各验证一遍

①拿一段真实写过的中文提示词,和它的英文翻译分别切,记下 Token 数之比——这就是日常多付的钱。②用在线 tiktokenizer 切 strawberry,看它被切成几块,再去问模型"这个词里有几个 r",把现象和原因对上。③试试切一段代码和一串数字,看看数字是怎么被切的(常常一位一位切,这解释了模型算数为什么费劲)。④想想:如果要给一个纯中文产品选模型,"中文 Token 效率"该怎么进选型清单?

13常见误区 · 实际情况

表 2 · 五个常见误区
可能以为实际情况
1 个 Token = 1 个词不是。英文常见词约 1 个,长词会拆成几块;中文常常 1 个字就 1~2 个 Token。
Tokenizer 是模型的一部分、可以随便换它在训练前定死,换了等于抽走模型的字典——编号对应的向量全乱。
模型看得见字母,只是懒得数真看不见。它的最小单位是 Token 整块,单个字母从未单独出现过。
词表越大越好是取舍:词表大→序列短省钱,但输出层更宽、更吃显存和训练成本。
中文更费 token 是因为中文"信息密度高"主要原因是训练语料以英文为主、中文的常见组合被合并得少,是工程结果不是语言宿命。

14自测 · 思考题

  1. 为什么要分词。模型为什么不能直接读汉字?
    参考答案

    神经网络只做数字运算,必须先把文字切成有限词表里的条目再换成编号;"有限"还因为输出层要为每个条目算一个概率。

  2. 三种粒度。为什么主流选子词?
    参考答案

    按字符→序列太长、单位无含义;按整词→词表爆炸且遇新词抓瞎;子词把常见词整块留、罕见词拆成常见片段,词表可控且永不遇生词。

  3. BPE。一句话说清它怎么工作。
    参考答案

    先全拆成字符,反复统计"最常相邻的一对"并合并成新块,重复到词表设定大小;得到的合并顺序表就是 tokenizer。

  4. 三个后果。为什么中文更费钱、模型数不清 strawberry 的 r?
    参考答案

    中文常用组合被合并得少(训练语料以英文为主),同义一段话 token 数常是英文 1.5~2 倍,而计费和窗口都按 token;字母数不清是因为模型看到的是 straw+berry 整块,从没见过单个字母。

16本章与下一章的连接

现在文字已经变成了一串编号。但编号本身没有含义——3245 和 3246 挨着,不代表这两个 Token 意思相近。模型需要的是能表达"含义"的东西。D13 · Embedding 与向量空间就干这件事:把每个编号换成一长串数字(向量),让"意思相近"变成"距离相近"——这是大模型能理解语言的真正起点,也解释了 A03 的 RAG 为什么能"按语义搜索"。
