Embedding 与向量空间

D12 把文字切成了 Token 并换成编号。但编号只是身份证号:3245 和 3246 挨着,不代表这两个词意思相近。模型需要的是能表达「含义」的东西。这一章讲的 Embedding(嵌入 / 词向量)就是那一步:把每个编号换成一长串小数,让意思相近的词,在几何空间里距离也近。这是大模型能"理解"语言的真正起点;也正是 A03 的 RAG 能按语义搜索、而不是按关键词匹配的原因。

图解骨架约 25 分钟,动手 + 精读约 3~4 小时。这一章的核心只有一句话:含义 = 位置。剩下的都是从这句话推出来的。

这一章要立起来的骨架

  • 为什么编号不够用——编号无含义、无距离,模型学不到"相近"
  • Embedding 是什么——每个 Token 一个向量,含义相近则位置相近
  • 向量怎么比——余弦相似度:比方向,不比长短
  • 位置编码——注意力本身不分先后,顺序要另外喂进去
  • 它长在哪——嵌入矩阵是模型的第一层,由训练学出来

接前面:续 D12 的编号(第 ② 站 → 第 ③ 站);向量距离的直觉续 D04 的降维可视化;词向量是 奠基论文 Word2Vec 那条线。通向后面:有了向量,注意力才有东西可算——D14 的 Q/K/V 全部由这些向量乘出来。工程上,这一章直接解释了 A03 RAG 的向量检索。

4一句话本质

Embedding:给每个 Token 分配一个多维空间里的坐标,让"意思"变成"位置"。于是"两个词像不像"这种模糊问题,变成了"两个点近不近"这种可以计算的几何问题——而计算,正是神经网络唯一会做的事。

为什么这一步是根本性的:编号 3245 和 3246 在数值上只差 1,但可能一个是"猫"一个是"轮胎"——编号的大小关系是任意的、不携带任何含义。如果直接把编号喂给网络,它会误以为 3245 和 3246 很像(这正是 D06 里"类别不能编成 1/2/3"那条规矩,在大模型上的同一个问题)。Embedding 的解法是:给每个 Token 配一个长度几百到几千的向量(比如 [0.21, -1.34, 0.88, …]),这些数字不是人填的,而是训练时学出来的——模型为了把"下一个词"预测准,自己就会把经常出现在相似语境里的词,安排到相近的位置上。学完之后,"猫"和"狗"的向量就会靠得很近,"猫"和"轮胎"离得很远。含义没有被定义,而是被"位置"编码了出来。

7编号为什么不够用

Token 编号是任意分配的身份证号:数值大小不代表任何含义,相邻编号也毫无关系。直接把它当数字喂进网络,等于告诉模型一堆假信息(3245 比 3244 "大一点")。这正是 D06 那条"无序类别不能编成 1/2/3"的规矩,只是搬到了几万个词的规模上。

那 D06 的解法(one-hot)行不行?理论上行,实际不行。one-hot 会把每个词变成一个长度 = 词表大小(几万到十几万)的向量,里面只有一个 1、其余全 0。三个致命问题:①太大——每个词几万维,一句话就爆内存;②全都一样远——任意两个 one-hot 向量的距离完全相等,"猫"和"狗"并不比"猫"和"轮胎"更近,含义信息一点没有;③没法泛化——模型对每个词都得单独学一遍。Embedding 就是对这三点的回答:把几万维压成几百维的稠密向量(每一维都是有意义的小数,不是一堆 0),而且这些位置是学出来的,天然带上了"谁和谁像"的信息。

那这些向量到底长什么样、凭什么说它装了含义。

8Embedding:含义变成位置

每个 Token 对应一个长度固定的向量(常见 512 / 768 / 4096 维),可以想成高维空间里的一个点。训练之后,这些点的排布本身就编码了语义:经常出现在相似语境里的词,会被安排到相近的位置。

为什么训练能做到这一点?因为模型的任务是"预测下一个词"。"猫"和"狗"经常出现在几乎一样的句子里(「我养了一只__」「__在睡觉」),要把这些位置都预测好,最省力的办法就是给这两个词相近的向量——于是相似的语境,逼出了相近的位置。这个思想叫分布式假设:一个词的意思,由它周围经常出现的词决定。经典的 Word2Vec(2013,见资源库的奠基论文)第一次把它做出了名场面:国王 − 男人 + 女人 ≈ 女王——连"性别"这种抽象关系,都变成了空间里一个可加减的方向。今天的大模型不再单独训词向量,而是把嵌入矩阵作为模型第一层和整个网络一起训,但道理是同一个。

既然含义是位置,那"像不像"就要能算出来。

9余弦相似度:比方向,不比长短

衡量两个向量像不像,最常用余弦相似度:看两者方向的夹角,不看长度。夹角越小越相似,取值 −1 到 1(1 = 同向 / 意思最近,0 = 无关,−1 = 相反)。RAG 的"向量检索"算的就是这个数。

为什么比方向不比长度:向量的"长度"往往受词频等无关因素影响(常用词的向量可能整体偏长),而"指向哪个方向"才稳定地对应含义。所以业界统一用余弦。算法很简单:把两个向量逐位相乘再求和(点积),除以两者长度——就是夹角的余弦。落到实处:A03 的 RAG 里,问题被转成一个向量,库里每段文字也各有一个向量,系统就把问题向量和每段的余弦相似度算一遍,取最高的几段拼进上下文。"按语义搜索"这个听着玄的能力,底下就是这一个夹角。顺带一提,D04 的 PCA/UMAP 就是把这些几百维的点压到二维,好让人眼能看见图 2 那种簇。

还差一件事:向量里没有"先后"。

10位置编码:把顺序也喂进去

词向量只表示"这个词是什么",不表示"它排第几"。而 注意力是同时看所有词的(这正是它能并行的原因,D09),天生分不清先后。所以要额外把"位置"也编码成向量,加到词向量上——这就是位置编码(positional encoding)。

为什么必须补:D09 讲过,RNN 靠"从左到右一个个读"天然带着顺序;而 Transformer 把这个顺序扔了换来并行,代价就是"猫追狗"和"狗追猫"在它眼里会变成同一堆词。补救办法很朴素:给第 1 个位置、第 2 个位置……各自也造一个向量,和该位置的词向量相加,于是每个输入既带"是什么"又带"在第几"。早期用固定的正弦波公式生成(不用学、能外推到更长句子),现在很多模型改用可学习的或旋转式位置编码(RoPE),但目的完全一样。记住这一句就够:注意力不分先后,顺序是另外加进去的。

最后把这些向量在模型里的具体位置落实一下,并动手算一次相似度。

11组装:嵌入矩阵 + 动手算相似度

模型里存着一张嵌入矩阵:行数 = 词表大小,列数 = 向量维度。查 Token 编号就是取出对应的那一行。这张表是模型的第一层,和整个网络一起训练:

embedding_demo.pypython
import torch
import torch.nn as nn

VOCAB, DIM = 50000, 768                 # 词表 5 万条,每个 Token 用 768 维向量表示
emb = nn.Embedding(VOCAB, DIM)          # 嵌入矩阵:50000 行 × 768 列,参数由训练学出

ids = torch.tensor([3245, 8721, 522])   # D12 切出来的三个 Token 编号
vecs = emb(ids)                         # 查表:取出对应的三行
print(vecs.shape)                       # torch.Size([3, 768]) —— 3 个词,各 768 维

# 余弦相似度:比方向不比长短(RAG 的向量检索算的就是它)
cat  = torch.randn(768)                 # 假设这是"猫"的向量
dog  = cat + 0.1 * torch.randn(768)     # "狗":语境相似 → 位置相近
tire = torch.randn(768)                 # "轮胎":毫不相干 → 随机方向

cos = nn.CosineSimilarity(dim=0)
print(f"猫-狗   {cos(cat, dog):.3f}")    # 接近 1:方向几乎一致
print(f"猫-轮胎 {cos(cat, tire):.3f}")   # 接近 0:高维空间里随机两向量近乎垂直

三点值得留意:①nn.Embedding 本质就是"一张可训练的查找表",没有别的魔法;②输出形状 [3, 768] 正是后面注意力要吃的东西——D14 的 Q/K/V 全从这里乘出来;③最后那个实验有个反直觉的结论:高维空间里随机取两个向量,余弦几乎总是接近 0(近乎垂直)——所以"相似度 0.8"在几百维里已经是很强的信号了,这也是 RAG 调阈值时要有的常识。

13常见误区 · 实际情况

表 2 · 五个常见误区
常见理解实际情况
向量里每一维都对应一个能命名的属性(如"性别维")基本不是。维度是训练自然形成的,通常没有人类可命名的含义;可解释的是方向和距离。
Embedding 是人工设计的编码表是训练学出来的参数矩阵,和网络其它权重一起更新。
相似度要用欧氏距离文本向量业界默认余弦(比方向不比长度);长度常受词频等无关因素影响。
有了词向量就不用管顺序要管。注意力同时看所有词、不分先后,顺序靠位置编码另外加。
一个词永远只有一个固定向量静态词向量(Word2Vec)是;但大模型里,同一个词在不同上下文中的表示会被注意力改写(D14 起)。

14自测 · 思考题

  1. 为什么不用编号。Token 编号直接喂给模型有什么问题?one-hot 又为什么不行?
    参考答案

    编号大小是任意的,直接当数字会让模型误以为相邻编号相近;one-hot 虽无此问题,但维度=词表大小太大、任意两词距离全相等(无含义)、且无法泛化。

  2. 含义=位置。训练为什么会把"猫"和"狗"放得很近?
    参考答案

    分布式假设:它们常出现在几乎相同的语境里,要把这些位置的下一个词都预测好,最省力的解就是给它们相近的向量。

  3. 余弦相似度。为什么比方向不比长度?它和 RAG 什么关系?
    参考答案

    长度受词频等无关因素影响,方向才稳定对应含义。RAG 的向量检索就是算问题向量与各文本块向量的余弦,取最高的几段。

  4. 位置编码。为什么需要它?
    参考答案

    注意力同时看所有词、天生不分先后(这也是它能并行的原因),所以要把"排第几"单独编码成向量加到词向量上,否则"猫追狗"和"狗追猫"无法区分。
