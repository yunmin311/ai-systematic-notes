注意力机制逐步手算

D09 用直觉讲过注意力:"处理某个词时,一步看全句、按相关度加权"。D13 把每个词变成了带含义的向量。这一章要做的,是把那句直觉拆成四步算术,用一个 3 个词的小例子从头算到尾——Q/K/V 从哪来、分数怎么打、softmax 之后怎么加权求和。这四步算完,今天所有大模型(GPT、Claude)最核心的那块机制,就不再是黑箱了。

图解骨架约 40 分钟,跟着手算 + 精读约 4~6 小时。这一章务必拿纸笔跟着算一遍——例子里的数字是特意挑的,口算就能对上。

读完这一章,我脑子里会立起来的骨架

4一句话本质

注意力:每个词都拿自己的"查询"去和全句每个词的"标签"比一次相似度,得到一组权重;再按这组权重,把全句每个词的"内容"加权平均起来,作为这个词的新表示。一句话——按相关度做一次加权平均。

用图书馆打比方一次就够:我带着一个需求(Query,"我想找和'它'有关的信息")去查书;每本书封面上贴着标签(Key,"我是猫""我是动作");我把需求和每个标签比一比,得出每本书的相关度;然后按相关度,把每本书的内容(Value)按比例抄一部分下来汇总。这就是全部。之所以显得神秘,是因为论文里写成了矩阵公式;可一旦拆成"比相似 → 归一化 → 加权平均"三个动作,我会发现每一步都是小学算术。而它之所以强大,是因为这个操作让任意两个词直接建立联系(不像 RNN 要一路接力),而且所有词可以同时算(GPU 满载)——D09 说的那两堵墙,就是这么被推倒的。

先认清三个角色。它们看着玄,其实都是同一个向量乘出来的。

7Q / K / V:三个角色,一个来源

每个词的向量(来自 D13)分别乘上三个不同的权重矩阵 W_Q、W_K、W_V,得到三个新向量:Q(Query,查询:我在找什么)、K(Key,标签:我是什么)、V(Value,内容:我能提供什么信息)。三个矩阵都是训练学出来的参数。

为什么要拆成三个而不直接用原向量:因为"我作为提问方想找什么"和"我作为被查方怎么介绍自己"是两回事。同一个词"猫",当它是查询时可能在找"动作是什么",当它是被查对象时要宣告"我是一个动物名词"。用三个不同矩阵投影,就让模型能分别学这三种角色。理解上抓住一点即可:Q 和 K 用来算"该不该看",V 才是真正被搬运的信息。所以 Q 和 K 的维度必须一样(要做点积),V 的维度可以不同(它只负责被加权求和)。

有了三个角色,注意力就只剩四步算术。

8四步算术

①打分:拿这个词的 Q,和每个词的 K 做点积,得到一组原始分数。②缩放:全部除以 √d_k(d_k 是 Q/K 的维度),防止分数太大。③softmax:把分数变成加起来等于 1 的权重。④加权求和:按权重把所有 V 相加,得到输出。

逐步说清每步为什么:①打分——点积就是 D13 说的"方向有多一致",两个向量越同向、分数越大,即"越相关"。②缩放——维度一高,点积的数值会变得很大,直接送进 softmax 会让结果极端(几乎全部权重压到一个词上),梯度也难传;除以 √d_k 把量级拉回来,这是论文里那个 √d 的全部理由。③softmax(D02 学过)——把任意实数变成 0~1 且总和为 1 的权重,于是"相关度"变成了"注意力分配比例"。④加权求和——按比例把各词的 V 混合起来。输出就是这个词"参考了全句之后的新表示"。写成一行公式就是论文里的 softmax(QKᵀ/√d)V——这一行,就是刚说的四步。

下面用一个 3 个词的例子,把这四步真算一遍。

9手算:三个词的完整一遍

句子:「猫 追 老鼠」,现在要算第 3 个词"老鼠"的注意力输出(即:它该从全句吸收多少信息)。为了能口算,取 d_k = 4,数字都特意挑成整数。

第 0 步:准备好 Q/K/V。(实际由词向量乘三个矩阵得到,这里直接给结果)

表 2 · 例子的 Q / K / V(d_k=4,V 取 2 维便于口算)
词K(标签)V(内容)
猫[1, 0, 1, 0][10, 0]
追[0, 1, 0, 1][0, 10]
老鼠(也是本次的查询方)[1, 0, 0, 1][5, 5]

本次查询 Q(老鼠) = [1, 0, 1, 0](它在找"和自己相关的名词/动作")。

第 1 步 · 打分(Q 与每个 K 做点积):逐位相乘再求和。

  • 对「猫」:1×1 + 0×0 + 1×1 + 0×0 = 2
  • 对「追」:1×0 + 0×1 + 1×0 + 0×1 = 0
  • 对「老鼠」自己:1×1 + 0×0 + 1×0 + 0×1 = 1

第 2 步 · 缩放:除以 √d_k = √4 = 2 → 分数变成 [1, 0, 0.5]。

第 3 步 · softmax:先各取 e 的幂:e¹≈2.72、e⁰=1、e⁰·⁵≈1.65,总和 ≈ 5.37;各自除以总和:

看向缩放后分数e 的幂权重
猫12.720.51(最相关)

老鼠(自己)0.51.650.31

第 4 步 · 加权求和:按权重把各词的 V 混起来。

输出 = 0.51×[10, 0] + 0.19×[0, 10] + 0.31×[5, 5] = [5.1, 0] + [0, 1.9] + [1.55, 1.55] = [6.65, 3.45]

读一下这个结果:输出向量里"猫"那一路的成分(6.65)明显压过"追"(3.45),说明这一步注意力判断——理解"老鼠"时,最该参考的是"猫"。这正是注意力干的事:它没有改变任何词的原意,只是让每个词按相关度,把全句的信息吸收进自己的新表示里。真实模型里唯一的不同是:维度是几百而不是 4、句子是几千词而不是 3、这套运算并行地对每个词各做一遍——算术本身,和我刚算的一模一样。

把这四步"每个词都做一遍""同时做好几套",就是自注意力和多头。

10自注意力与多头

自注意力(self-attention):句子里每个词都当一次查询方,对全句算一遍上面的四步——所以 n 个词就得到 n 个新向量。多头(multi-head):同时准备好几套独立的 W_Q/W_K/W_V(比如 8 套、32 套),各算各的,最后把结果拼起来——每一"头"可以专注一种关系。

为什么叫"自"注意力:因为 Q、K、V 全都来自同一个句子(自己看自己),区别于早期机器翻译里"用译文查原文"的交叉注意力。为什么要多头:一个句子里同时存在很多种关系——谁是谁的主语、代词指代谁、哪个形容词修饰哪个名词……只用一套 Q/K/V,模型被迫把这些关系挤在一个加权平均里;开 8 个头,就等于同时用 8 种不同的"看法"扫一遍全句,一个头盯语法主谓、一个头盯指代、一个头盯位置邻近……最后拼接融合。实践中这带来明显提升,代价只是把维度切成几份分给各头(总计算量差不多)。记住:多头不是算得更细,而是同时看几种不同的关系。

最后两件必须知道的:一条规矩,一个代价。

11因果掩码,与平方级代价

因果掩码(causal mask):生成式模型在预测第 t 个词时,不许看第 t 个之后的词——否则就是抄答案。做法是在 softmax 之前,把"未来位置"的分数设成负无穷,权重自然变 0。平方级代价:每个词都要和每个词算一次分,n 个词就是 n×n 次——长度翻倍,计算量变四倍。

掩码解释了一个我天天见的现象:大模型是一个词一个词往外蹦的(第 8 章那个循环)。因为训练时它就被要求"只根据前文预测下一个",掩码保证了这条规矩;推理时自然也只能逐个生成。平方级代价则解释了另外两件事:①上下文窗口为什么有上限——不是不想给我更长,是 n² 的计算和显存吃不消;②长提示词为什么贵得快——不是线性贵,是接近平方地贵。D17 会讲业界怎么用 KV cache 和各种高效注意力来缓解。这两条是注意力的"规矩"和"账单",工程上比公式本身更常被用到。

用十几行代码把四步写出来,和手算结果对上。

12组装:十几行实现注意力

下面的代码就是第 8 节那四步的逐行翻译,并用第 9 节的例子验算——跑出来应该正好是 [6.65, 3.45]:

attention_by_hand.pypython
import torch
import torch.nn.functional as F

# 例子:「猫 追 老鼠」,给出每个词的 K 和 V(实际由词向量乘 W_K / W_V 得到)
K = torch.tensor([[1., 0., 1., 0.],     # 猫
                  [0., 1., 0., 1.],     # 追
                  [1., 0., 0., 1.]])    # 老鼠
V = torch.tensor([[10., 0.],            # 猫的内容
                  [0., 10.],            # 追的内容
                  [5., 5.]])            # 老鼠的内容
q = torch.tensor([1., 0., 1., 0.])      # 本次查询:老鼠的 Q

d_k = K.shape[1]                        # = 4
scores = K @ q                          # ① 打分:点积 → tensor([2., 0., 1.])
scores = scores / d_k ** 0.5            # ② 缩放:÷√4 → tensor([1.0, 0.0, 0.5])
weights = F.softmax(scores, dim=0)      # ③ softmax → tensor([0.506, 0.186, 0.307])
out = weights @ V                       # ④ 加权求和 → tensor([6.65, 3.45])

print("权重:", weights)                  # 「猫」占一半以上 = 最该参考它
print("输出:", out)                      # 和手算一致

# 真实模型的写法:一次算全句所有词(Q 是矩阵不是单个向量),再加因果掩码
def attention(Q, K, V, causal=False):
    s = Q @ K.T / K.shape[-1] ** 0.5              # 所有词两两打分:n×n
    if causal:                                     # 生成时:不许看未来
        s = s.masked_fill(torch.triu(torch.ones_like(s), 1).bool(), float('-inf'))
    return F.softmax(s, dim=-1) @ V                # softmax 后加权求和

对照着看:K @ q 是第 1 步,/ d_k**0.5 是第 2 步,F.softmax 是第 3 步,weights @ V 是第 4 步——四行代码,四步算术,和纸上算的一模一样。下面那个 attention() 函数是真实写法:Q 换成矩阵一次算全句(Q @ K.T 出来就是 n×n 的分数表,平方级代价在这里看得见),masked_fill 那一行就是因果掩码——把上三角(未来位置)设成负无穷。整个大模型最核心的机制,到此已经完整地摆在我面前了。

15自测 · 思考题

  1. 三角色。Q、K、V 各是什么、从哪来?
    参考答案

    同一个词向量分别乘 W_Q/W_K/W_V(可训练矩阵)得到:Q=我在找什么,K=我是什么(用于被匹配),V=我能提供的信息(被加权搬运)。Q 与 K 决定该不该看,V 是真正被搬的内容。

  2. 四步。不看资料复述注意力四步。
    参考答案

    ①Q 与各 K 点积打分 → ②除以 √d 缩放 → ③softmax 变成和为 1 的权重 → ④按权重对各 V 加权求和。即 softmax(QKᵀ/√d)V。

  3. 缩放。为什么要除以 √d?
    参考答案

    维度高时点积数值会很大,直接 softmax 会导致权重极端(几乎全压一个词)、梯度难传;缩放把量级拉回合适范围。

  4. 掩码与代价。因果掩码干什么?为什么长文本贵得快?
    参考答案

    掩码在 softmax 前把未来位置的分数设为 −∞,保证预测第 t 词时不偷看后文;代价方面每个词要和每个词打分,是 n² 级,长度翻倍开销约四倍。
