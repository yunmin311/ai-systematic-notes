预训练、微调与 RLHF

D15 造好了骨架,但那时它的参数全是随机数——什么也不会。从"一堆随机数"到"能聊天、会写码、还挺听话"的模型,中间是三个阶段:预训练(读海量文本,学会语言本身)、微调(学会照指令做事)、对齐(学会给出人更满意、更安全的回答)。这一章把三个阶段拆清,并算一笔实在的账:哪一段是几千万美元级、只有大厂能做,哪一段是几百块钱、自己就能上手。

图解骨架约 30 分钟,精读约 3~4 小时。这一章几乎没有数学,重点是看清整条生产链和每段的成本——它直接决定"想做一个自己的模型"时,该从哪一环切入。

这一章要立起来的骨架

  • 阶段一 · 预训练——用"预测下一个词"读海量文本,学到语言与世界知识
  • 阶段二 · 指令微调(SFT)——用高质量示范,把"续写"变成"照做"
  • 阶段三 · 对齐(RLHF / DPO)——用人类偏好,教它选人更满意的答法
  • 三段的成本——从几千万美元到几百块,差了五六个数量级
  • 参数高效微调(LoRA)——只训极小一部分参数,个人也能微调大模型
从哪来 · 到哪去

接前面:被训练的对象就是 D15 那副骨架;训练循环还是 D07 那五步;"预训练+微调"这个范式在 D11 已经用图像见过一次。通向后面:训好的模型怎么跑得起、跑得便宜,是 D17;而"对齐"这一段正是 A06 安全与评估在模型侧的源头。

4一句话本质

三个阶段可以概括成三句话:预训练——读遍海量文本,学会"语言长什么样、世界是怎么回事";指令微调——看少量高质量示范,学会"别人问我,我该照着做";对齐——根据人类的偏好打分,学会"同样一件事,人更喜欢哪种答法"。能力主要来自第一段,好用与安全主要来自后两段。

为什么必须分三段:预训练出来的"基座模型"其实只会续写——给它"如何煮鸡蛋",它可能续出"如何煮鸡蛋?如何煎鸡蛋?如何蒸鸡蛋?"(因为语料里这样的列表很常见),而不是作答。它有知识,但没有"被问就答"的习惯。指令微调用几万条"指令—优质回答"的示范,把这个习惯教给它。但示范只能告诉它"什么是对的",没告诉它"两个都对的回答里,哪个更好"——于是第三段用人类对回答的排序偏好再训一次,让它学会选更清楚、更有帮助、更安全的那种。三段的关系:预训练给能力,微调给形式,对齐给分寸。

7阶段一 · 预训练:读遍互联网

任务只有一个:预测下一个词。把海量文本(网页、书籍、代码,常以万亿 Token 计)喂进 D15 那副骨架,每次遮住后文、让它猜下一个 Token,猜错就调参数(D07 的五步循环)。重复上万亿次之后,它为了把这个游戏玩好,被迫学会了语法、事实、推理套路、代码规则——能力是"顺带"学到的。

为什么一个这么朴素的任务能学出这么多:因为要准确预测下一个词,模型必须理解上下文。"法国的首都是__"——要填对就得知道事实;"这段代码报错是因为__"——要填对就得懂代码逻辑;"他很生气,因为__"——要填对就得懂因果和情绪。预测下一个词是一个"考试题库无限大、且涵盖人类所有书面知识"的任务,把它做到极致,就顺带学会了几乎一切。这也是规模化(scaling)路线的根据:模型更大、数据更多、算力更足,这个预测就更准,能力也随之上涨。代价是极其昂贵——大模型的预训练动辄几千万美元、数千张顶级 GPU 跑数月,这一段基本只有大厂做得起。产物叫基座模型(base model):知识渊博,但只会续写、不会"听话"。

第二段便宜得多,但决定了它像不像个助手。

8阶段二 · 指令微调:学会照做

指令微调(SFT,Supervised Fine-Tuning):准备几万条高质量的"指令 → 理想回答"示范(多由人工撰写或精选),继续用同样的"预测下一个词"训练,只不过这次预测的是示范里的标准答案。训练后,模型的行为习惯从"续写文本"变成"回答问题"。

关键是理解它没有获得新知识,只是换了个说话方式。知识早在预训练阶段就有了;SFT 教的是格式和习惯:被问就答、答完就停、按要求分点、拒绝不该做的事。所以这一段的数据质量远比数量重要——几千条精心写的示范,常胜过几十万条凑数的。成本上它比预训练便宜好几个数量级(几千到几万美元级,用 LoRA 甚至能压到几百块),这也是开源社区能在别人的基座模型上做出各种专用助手的原因:基座别人出钱训,微调自己来。

第三段解决的是"两个都对,选哪个"。

9阶段三 · 对齐:RLHF 与 DPO

RLHF(基于人类反馈的强化学习)三步:①让模型对同一问题生成几个回答,请人排序哪个更好;②用这些排序训练一个奖励模型(它学会给回答打分,相当于把人的偏好压缩成一个打分器);③用强化学习调整模型,让它倾向于生成奖励模型打高分的回答。DPO 是近年的简化版:跳过奖励模型,直接用偏好数据一步优化,更简单也更稳。

为什么需要这一段:SFT 的示范只给了"一个正确答案",但现实里同一问题有无数种答法,好坏是程度问题——哪个更清楚、更有帮助、更少废话、更不容易被诱导做坏事。这些很难写成示范,却容易比较:给人看两个回答,他能立刻说出哪个更好。RLHF 正是利用了这一点:把"难以定义的好"转化成"容易表达的偏好"。这一段带来的提升非常直观——同一个基座模型,对齐前后的"好用程度"天差地别,ChatGPT 当年的惊艳很大程度就来自这里。同时,这也是安全与价值观注入的主要环节:模型该拒绝什么、该如何拒绝,大多在这一步塑造(直接对应 A06 的安全话题,也是 AI 治理最实质的技术抓手之一)。代价:需要大量人工偏好标注,贵且慢;而且对齐过度会让模型变得啰嗦、过度拒绝——这就是所谓的"对齐税"。

把成本摊开看,就知道自己该切哪一环。

10三段成本账

三段的花费差五六个数量级:预训练以千万美元计,指令微调以千元到万元美元计(用 LoRA 可低至几百人民币),对齐则贵在人工标注而非算力。结论很实际:从零训一个大模型不是个人选项;但在别人的基座上微调,今天已是消费级显卡就能做的事。

最后一件最实用的事:什么时候才真该微调。

11LoRA,与"该不该微调"的判据

LoRA(低秩适配):冻住原模型的全部权重,只在每层旁边插入两个很小的矩阵去学"改动量"——可训练参数常常不到原模型的 1%,显存和成本因此暴降,一张消费级显卡就能微调一个 7B 模型。这是把 D11 的"冻结 + 只训一小部分"推到极致的做法。

但更重要的判断是:该不该微调。实践中大多数需求不需要微调,顺序应该是:①先把提示词写好(A01)——最快最便宜,能解决很大一部分问题;②需要它掌握私有资料 → 用 RAG(A03)——资料随时可更新,不用重训;③只有当要的是"固定的风格/格式/领域腔调",或要把大模型的能力压进一个小模型省钱时,才微调。一句常用判据:缺"知识"用 RAG,缺"行为方式"才微调。把它记住,能省掉大量无谓的训练。

用一段代码看看 LoRA 微调有多短。

12组装:LoRA 微调的骨架

用 Hugging Face 的 PEFT 库,给一个开源基座模型加 LoRA 并微调,核心就这几行:

lora_sft.pypython
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model

MODEL = "Qwen/Qwen2.5-1.5B"                      # 别人训好的基座(阶段①的产物)
tok   = AutoTokenizer.from_pretrained(MODEL)
model = AutoModelForCausalLM.from_pretrained(MODEL)

# LoRA:冻住原权重,只在注意力的投影矩阵旁插入小矩阵学"改动量"
cfg = LoraConfig(
    r=8,                                         # 插入矩阵的秩:越小越省、表达力越弱
    lora_alpha=16,
    target_modules=["q_proj", "v_proj"],         # 挂在 D14 的 Q/V 投影上
    lora_dropout=0.05,
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, cfg)
model.print_trainable_parameters()
# 输出类似:trainable params: 1.1M || all params: 1.5B || trainable%: 0.07
# —— 只训 0.07% 的参数,单张消费级显卡就够

# 训练数据:几千条「指令 → 理想回答」示范(阶段②的原料),形如
#   {"instruction": "把这段话改写得更简洁", "output": "……"}
# 之后照常用 Trainer 或 D07 的五步循环训几轮即可;产物只有几十 MB 的 LoRA 权重,
# 用的时候和基座模型一起加载。

三点值得注意:①trainable% 那行是 LoRA 的全部魅力——0.07% 的可训练参数,却能显著改变模型行为;②产物是个几十 MB 的小文件(而不是几 GB 的完整模型),可以做很多个、按需切换;③target_modules 挂在 D14 的 Q/V 投影上——学到这里,这个参数名不再是天书。训练?还是 D07 那五步循环,从第一章到这里,那个循环一次都没变过。

15自测 · 思考题

  1. 三阶段。各用什么数据、各解决什么问题?
    参考答案

    预训练:海量无标注文本,预测下一个词,学语言与世界知识(给能力);SFT:几万条指令-回答示范,学会照做(给形式);对齐 RLHF/DPO:人类偏好排序,学会选更有帮助更安全的答法(给分寸)。

  2. 为什么这一个任务够用。"预测下一个词"为什么能学出这么多能力?
    参考答案

    要准确预测就必须理解上下文——事实、逻辑、代码规则、情绪因果都会影响下一个词,于是把这个任务做到极致就顺带学会了这些。

  3. RLHF。三步是什么?DPO 简化了哪一步?
    参考答案

    ①人对多个回答排序;②用排序训练奖励模型(打分器);③用强化学习让模型倾向高分回答。DPO 跳过奖励模型,直接用偏好数据一步优化。

  4. 选型。什么时候该微调?
    参考答案

    先试提示词;缺私有知识用 RAG;只有需要固定风格/格式/领域行为,或要把能力压进小模型省钱时才微调。判据:缺知识用 RAG,缺行为方式才微调。
