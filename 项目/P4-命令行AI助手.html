1成品长什么样

先看终点。跑起来后,终端里是这样一段对话——我输入,它逐字吐出回答,记得上文,输入 exit 退出:

终端 · python assistant.py
AI 助手已就绪(输入 exit 退出)
你 › 帮我想三个给猫咪起的名字
AI › 1. 豆豆  2. 布丁  3. 芝麻。要更优雅的还是更可爱的?
你 › 第二个不错,它是橘猫,再顺着起两个
AI › 顺着"布丁"的甜品风,给橘猫:焦糖、蛋挞。都暖橘色系~
# ↑ 它记得"布丁""橘猫"——这就是多轮对话状态在起作用
你 › exit
再见 👋

这个项目的本质:一个 while 循环,每轮把我的话追加进一个 messages 列表,连整段历史发给模型,再把回答流式打印出来、也追加回列表。就这么简单——但它是所有对话式 AI 应用的地基。

2动手前的准备

三样东西:

  1. Python 环境(3.9+)。终端能跑 python --version 即可。
  2. 装 SDK。这里用 OpenAI 的 Python 库(最通用;换 Claude 等只改几行,思路一样):
    终端bash
    pip install openai
  3. API 密钥放进环境变量——绝不写进代码(A07 红线:密钥=钱包,进了代码/git 就会泄露被盗刷)。在终端设一次:
    终端(当次会话有效)bash

# Windows PowerShell
$env:OPENAI_API_KEY="你的密钥"
花钱提示(A06)

调 API 按 token 计费,聊天很便宜(一次几分钱),但别把密钥泄露出去。用完这个项目,建议去平台给密钥设个消费上限,睡得安稳。

分四步,从"能回一句"一路加到"像样的助手"。每步都能单独跑、单独验证。

3第 1 步 · 最小闭环:能回一句话

先跑通"发一句、收一句"。这是整个项目的心脏:

assistant.py · v1python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])   # A07:密钥从环境变量读

resp = client.chat.completions.create(
    model="gpt-4o-mini",                    # 便宜够用的小模型(A06:按难度选)
    messages=[{"role": "user", "content": "用一句话介绍你自己"}],
)
print(resp.choices[0].message.content)      # 取出模型回答的文字

messages 是一个"对话记录"列表,每条有 role(谁说的)和 content(说了啥)——这正是 A01/A04 讲的上下文。create 把它发给模型,回答藏在 resp.choices[0].message.content 里。

✓ 里程碑

python assistant.py 能打印出一句模型的自我介绍,就说明密钥、SDK、调用全通了。这一关过了,后面都是加料。

4第 2 步 · 多轮对话:让它记得上文

单次问答不够,要能连续聊。办法:开一个 messages 列表一直往里追加,每轮把整段历史发过去(A04 的"状态"):

assistant.py · v2python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

# A01:系统提示词,一句话定角色和风格
messages = [{"role": "system", "content": "你是简洁友好的中文助手,回答尽量短。"}]

print("AI 助手已就绪(输入 exit 退出)")
while True:                                  # 对话主循环
    user_input = input("你 › ")
    if user_input.strip() == "exit":
        print("再见 👋"); break

    messages.append({"role": "user", "content": user_input})   # 追加我的话
    resp = client.chat.completions.create(model="gpt-4o-mini", messages=messages)
    answer = resp.choices[0].message.content
    print("AI ›", answer)
    messages.append({"role": "assistant", "content": answer})  # 把回答也追加回去 ← 关键

最关键的是最后一行:把模型的回答也追加回 messages。下一轮就带着完整的一来一回发过去,模型才"记得"。漏了这行,它就成了每句都失忆的金鱼。

✓ 里程碑

连问两句相关的(如"推荐本书"→"它讲什么"),它能接住上文,就说明多轮状态成立了——这就是 A04 里 agent 状态的最小版。

5第 3 步 · 流式输出:打字机效果

现在它是"憋十几秒、整段蹦出来"。改成边生成边逐字打印(A07 的流式),体感立刻不一样。只需给 create 加 stream=True,然后逐块取字:

assistant.py · v3(替换第 2 步里的调用部分)python
    messages.append({"role": "user", "content": user_input})

    stream = client.chat.completions.create(
        model="gpt-4o-mini", messages=messages, stream=True,   # ← 开流式
    )
    print("AI › ", end="", flush=True)
    answer = ""
    for chunk in stream:                        # 一块一块地收
        delta = chunk.choices[0].delta.content  # 这一块新增的文字(可能为空)
        if delta:
            print(delta, end="", flush=True)    # 立刻打印,不换行、不缓冲
            answer += delta                      # 同时攒起完整回答
    print()                                      # 收尾换行
    messages.append({"role": "assistant", "content": answer})   # 攒好的完整回答入历史

要点:stream=True 让模型逐块返回;print(delta, end="", flush=True) 里的 flush=True 是"立刻显示别攒着"——少了它就看不到打字机效果。同时用 answer 把碎块拼回完整的一句,才能存进历史。

✓ 里程碑

回答像打字一样一个字一个字冒出来,就成了。总时间没变,但"干等"变成了"边读边等"(A07 图 3)。

6第 4 步 · 出错不崩:错误处理与收尾

最后一步把它从"玩具"变"能用":网络会抖、接口会超时、我会手滑按 Ctrl+C。用 try/except 兜住,别让一次报错掀翻整个程序(A06/A07):

assistant.py · v4(把调用包进 try)python
    try:
        stream = client.chat.completions.create(
            model="gpt-4o-mini", messages=messages, stream=True,
        )
        print("AI › ", end="", flush=True)
        answer = ""
        for chunk in stream:
            delta = chunk.choices[0].delta.content
            if delta:
                print(delta, end="", flush=True); answer += delta
        print()
        messages.append({"role": "assistant", "content": answer})

    except KeyboardInterrupt:                 # 我按了 Ctrl+C
        print("\n再见 👋"); break
    except Exception as e:                     # 网络/接口出错:提示但不崩
        print(f"\n[出错了,再试一次] {e}")
        messages.pop()                          # 把这轮没答成的用户消息撤回,保持历史干净

两个细节值得记:出错时 messages.pop() 把"这轮没答成功的提问"撤掉,避免脏历史让下一轮更乱;KeyboardInterrupt 单独接,让 Ctrl+C 优雅退出而不是喷一屏红字。这就是 A06 说的"假设会出错、把它当主线设计"。

✓ 里程碑 · 完成

拔掉网线问一句,它提示"出错了,再试一次"而不是崩溃;按 Ctrl+C 干净退出。到这,一个能给别人演示的终端 AI 助手就做完了。

9进阶扩展

再往上加(选做)

让它更像真产品

①限制历史长度:对话太长会越来越贵(A06 成本)。当 messages 超过 N 条时,保留 system + 最近若干条(这就是 A05 的上下文管理雏形)。②存档与续聊:退出时把 messages 存成 JSON,下次启动读回来。③加个 system 开关:命令行参数选"简洁版/详细版/翻译版"不同人设(A01)。④换模型对比:同一问题分别用小模型和大模型,感受质量与成本的差(A06)。
