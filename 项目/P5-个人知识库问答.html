项目 · Project P5

个人知识库问答(RAG)

P4 的助手只会用模型脑子里的知识,不知道自己的资料。这个项目给它接上一个"随身资料库":把一堆笔记(.md/.txt)做成能基于文档、带出处回答的问答机——这就是 A03 的 RAG 落地。我们从零手写整条链(切块 → 算向量 → 检索 → 拼接 → 生成),不用现成框架,好让人亲眼看清"语义检索"到底怎么工作。

难度 入门+ 语言 Python 用时 3~5 小时 前置 A03 · P4 产出 能问自己笔记的问答机

做完这个项目,会有 / 会做

  • 一个能回答"我自己文档里问题"的命令行问答机,还给出处
  • 亲手写出一条完整 RAG 链,不再是黑箱调库
  • 会把长文档切块、算 embedding、存成向量索引
  • 会用余弦相似度做"语义检索",找出最相关的片段
  • 会写"只依据资料回答、标出处、没有就说不知道"的提示词
这个项目用到哪些章

主力是 A03(RAG 全链路)、第 8 章(Embedding=意思近则向量近);生成那步复用 P4 的调用与提示词骨架。做完它,把"检索"包成一个工具,就通向 P6 的 Agent。

1成品长什么样

把笔记放进一个 docs/ 文件夹,跑起来后就能这样问——它会基于文档回答,并标出答案来自哪一块:

终端 · python rag.py
已索引 docs/ 下 12 个片段。开始提问(exit 退出)
问 › 我上次记的关于「上下文管理」的三种做法是什么?
答 › 笔记里写了三种:①裁剪旧轮次 ②压缩成要点 ③检索回相关片段。
      [来源 1] A05-harness.md  [来源 2] 学习心得.md
# ↑ 答案来自你的文档,还标了出处——可核对,不怕它编
问 › 量子计算机怎么造?
答 › 你的资料里没有相关内容,我无法回答。
# ↑ 资料里没有就老实说不知道,这正是 RAG 减少幻觉的关键

RAG 分两半:建库(一次性)——把文档切块、每块算成向量、存起来;问答(每次)——把问题也算成向量,找最相近的几块,塞进提示词让模型照着答。这个项目就是把这两半各写一遍。

生产做法(A03)

这里用 numpy 手算相似度,是为了看清原理——文档几千块以内够快。真做产品会把向量存进专门的向量数据库、或直接用 LlamaIndex/LangChain(几行搞定),原理还是这一套。先懂再用框架,不亏。

分四步,正好对着图 1 的两阶段:第 1–2 步建库,第 3–4 步问答。

3第 1 步 · 读文档 + 切块

先把 docs/ 里每篇读进来,切成一小段一小段(A03 的切块)。切太大检索不准、切太小丢上下文,这里按字数切、块间留点重叠防止把一句话拦腰截断:

rag.py · 建库(1/2)python
import os, glob

def chunk_text(text, size=500, overlap=80):
    """把一篇长文本切成若干块,块之间重叠 overlap 个字符。"""
    chunks, i = [], 0
    while i < len(text):
        chunks.append(text[i:i + size])
        i += size - overlap            # 下一块往前挪,留出重叠
    return chunks

def load_chunks(folder="docs"):
    """读 folder 下所有 .md/.txt,切块,记住每块来自哪个文件。"""
    items = []
    for path in glob.glob(os.path.join(folder, "*.md")) + glob.glob(os.path.join(folder, "*.txt")):
        text = open(path, encoding="utf-8").read()
        for c in chunk_text(text):
            items.append({"text": c, "source": os.path.basename(path)})   # 记住出处
    return items

chunks = load_chunks()
print(f"读到 {len(chunks)} 个片段")

每个片段存成一个字典:text(内容)+ source(哪个文件)。source 现在就记好,后面回答才能标出处。

✓ 里程碑

运行后打印"读到 N 个片段",N 合理(比如 3 篇笔记切出十几块),第 1 步就成了。

4第 2 步 · 算 embedding,建索引

把每块文字送去算成一个向量(第 8 章:意思近的文字,向量也近)。存下来,索引就建好了:

rag.py · 建库(2/2)python
import numpy as np
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

def embed(texts):
    """把一批文字变成一批向量(一次调用批量算,省钱又快)。"""
    resp = client.embeddings.create(model="text-embedding-3-small", input=texts)
    return [np.array(d.embedding) for d in resp.data]

vectors = embed([c["text"] for c in chunks])     # 批量算所有块的向量
for c, v in zip(chunks, vectors):
    c["vec"] = v                                  # 把向量挂回每个片段
print("索引建好了 ✓")

关键是批量算:一次把所有块的文字传进去,比一块调一次省得多(A06 成本)。算完把向量 vec 挂回每个片段,索引就是内存里这个 chunks 列表——每项有 文字 + 出处 + 向量。

✓ 里程碑

打印"索引建好了",且没报错,说明 embedding 调用通了。图 1 的上排(建库)完成。

5第 3 步 · 检索:给问题找最相近的块

问答阶段的核心。把问题也算成向量,用余弦相似度衡量它和每个块的"意思接近程度",取最高的几块(A03 的语义检索):

rag.py · 问答(1/2)python
def cosine(a, b):
    """余弦相似度:两个向量方向越一致,值越接近 1(意思越近)。"""
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

def retrieve(question, k=3):
    q_vec = embed([question])[0]                          # 问题也算成向量
    scored = [(cosine(q_vec, c["vec"]), c) for c in chunks]
    scored.sort(key=lambda x: x[0], reverse=True)         # 按相似度从高到低排
    return [c for score, c in scored[:k]]                 # 取最相近的 k 块

就这么朴素:算问题向量、跟每块比一下、排序、取前 k。这一步准不准,几乎决定整个 RAG 的成败(A03 说的"命门")。想看它到底找了啥,把 scored[:k] 的分数打印出来一眼就明白。

✓ 里程碑

随便传一个问题给 retrieve(),打印返回块的 source 和前几十字——命中的块确实和问题相关,检索就成了。

6第 4 步 · 拼上下文 + 生成 + 出处

最后一步:把检索到的块拼进提示词,明确要求模型只依据资料回答、标出处、找不到就说不知道(A03 收口 + A01 提示词),再套上 P4 的对话循环:

rag.py · 问答(2/2)python
def answer(question):
    top = retrieve(question, k=3)
    context = "\n\n".join(
        f"[来源:{c['source']}] {c['text']}" for c in top    # 每块带上出处
    )
    prompt = (
        "只根据下面的资料回答问题,并在末尾用 [来源:文件名] 标注依据。\n"
        "如果资料里没有相关内容,就直说「你的资料里没有相关内容」,不要编。\n\n"
        f"资料:\n{context}\n\n问题:{question}"
    )
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": prompt}],
    )
    return resp.choices[0].message.content

print(f"已索引 docs/ 下 {len(chunks)} 个片段。开始提问(exit 退出)")
while True:                                    # 复用 P4 的对话循环
    q = input("问 › ").strip()
    if q == "exit": break
    try:
        print("答 ›", answer(q))
    except Exception as e:
        print("[出错了,再试一次]", e)

提示词里那两句约束是 RAG 减少幻觉的关键:只依据资料 + 没有就说不知道 + 标出处。少了它,模型会拿资料当引子、继续自由发挥,出处也无从核对。到这,图 1 下排(问答)就通了。

✓ 里程碑 · 完成

问一个笔记里有的问题,它据实回答并标来源;问一个笔记里没有的,它说"资料里没有"。两种都对,整个 RAG 就跑通了——就是本章开头那段效果。

7跑起来

把四步的代码按顺序放进一个 rag.py(建库两段在前、问答两段在后),放好 docs/,然后:

终端bash
python rag.py

第一次启动会花几秒算所有块的向量(建库),之后每次提问都很快。就有了一个"能回答自己笔记"的问答机——把 docs/ 换成任何资料(产品手册、课程讲义、会议记录),它立刻就懂那些内容。

再往上加(选做)
