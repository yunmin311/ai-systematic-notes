一个小 Agent

前面的程序,路径都是我写死的。这个项目造一个真正的 Agent:给模型几个工具(算数、查时间、查我的知识库),让它自己在循环里决定该调哪个、看到结果再决定下一步,直到把任务办完——这就是 A04 的 ReAct 循环 + A05 的 harness 落成代码。我会亲手写出那个"想 → 做 → 看 → 再想"的引擎,还会给它装上防跑飞的 max_steps 闸。

难度 中级 语言 Python 用时 4~6 小时 前置 A04 · A05 · P4 产出 会用工具的 agent

做完这个项目,我会有 / 会做

  • 一个能自己调工具、多步完成任务的命令行 agent
  • 亲手写出 agent loop:模型选工具 → 执行 → 结果喂回 → 再想
  • 会用 JSON schema 描述工具、让模型看得懂怎么调(A02)
  • 会写工具分发:按模型的选择跑对应函数、把结果还回去
  • 会用 max_steps 兜底防死循环(A05 harness 的关键闸)

骨架是 A04(ReAct 循环、工具、状态)+ A05(loop 工程化、max_steps 兜底);工具描述用 A02 的函数调用;对话循环复用 P4;还能把 P5 的检索包成一个工具接进来。

1成品长什么样

跑起来后,给它一个需要动手才能答的任务,它会自己一步步调工具——中间的"想/做/看"我们打印出来,让我看清它在循环里怎么推进:

终端 · python agent.py
小 Agent 就绪(工具:calculator、get_time)。输入任务:
任务 › 现在几点?再帮我算 1200 除以 100 等于几小时
  · 想:先查时间          → 调 get_time()
  · 看:2026-08-16 15:40
  · 想:再算 1200/100     → 调 calculator("1200/100")
  · 看:12.0
  · 想:两个都拿到了,可以答了
答 › 现在是 15:40;1200 除以 100 等于 12,也就是 12 小时。

Agent 的本质:一个 循环。每轮把整段历史发给模型,模型要么说"调某个工具"(程序就去执行、把结果塞回历史)、要么直接给最终答案(循环结束)。模型是决策的脑子,我的代码是让它能行动的手脚和轨道。

3第 1 步 · 定义工具

工具有两面:一面是真正干活的 Python 函数,另一面是给模型看的说明书(JSON schema,A02)——模型靠说明书决定"这个任务该调哪个、传什么参数":

agent.py · 工具python
from datetime import datetime

# —— 干活的函数 ——
def calculator(expr):
    return str(eval(expr))            # 教学用;生产别直接 eval(A06 安全:见常见坑)

def get_time():
    return datetime.now().strftime("%Y-%m-%d %H:%M")

# —— 给模型看的说明书(A02 的 schema)——
tools = [
    {"type": "function", "function": {
        "name": "calculator",
        "description": "计算一个数学表达式,例如 1200/100",
        "parameters": {"type": "object",
            "properties": {"expr": {"type": "string", "description": "要计算的表达式"}},
            "required": ["expr"]}}},
    {"type": "function", "function": {
        "name": "get_time",
        "description": "返回当前日期和时间",
        "parameters": {"type": "object", "properties": {}}}},
]

# 名字 → 函数 的对照表,执行时按名字找(第 3 步用)
REGISTRY = {"calculator": calculator, "get_time": get_time}

description 写得好不好,直接决定模型选得对不对(A02/A01)。REGISTRY 是"工具注册表"(A05 harness 的一部分):模型只会说"我要调 calculator",真正去跑函数的是我的代码,靠这张表按名字找。

✓ 里程碑

单独调 calculator("1200/100") 返回 "12.0"、get_time() 返回当前时间,两个函数本身没问题,就可以进循环了。

4第 2 步 · 写 agent loop

心脏来了。一个 for 循环给模型多步机会:每轮把历史 + 工具说明发过去,模型要么要求调工具,要么给最终答案(图 1):

agent.py · 循环python
import os, json
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])
MAX_STEPS = 6                                    # A05:防死循环的闸

def run_agent(task):
    messages = [{"role": "user", "content": task}]     # 状态:一路累积(A04)

    for step in range(MAX_STEPS):                       # 循环:给它多步机会
        resp = client.chat.completions.create(
            model="gpt-4o-mini", messages=messages, tools=tools,
        )
        msg = resp.choices[0].message
        messages.append(msg)                            # 把这轮的决定记进历史

        if not msg.tool_calls:                          # 模型不调工具了 = 能答了
            return msg.content                          # 输出最终答案,跳出循环

        run_tool_calls(msg.tool_calls, messages)        # 要调工具 → 第 3 步处理

    return "(超过步数上限,没能完成)"                    # 兜底:防跑飞

对照图 1:for step 是循环;tools=tools 把说明书递给模型;msg.tool_calls 有没有,就是模型在"想:该调工具还是能答了"。没有 → 返回答案(跳出);有 → 去执行(下一步)。MAX_STEPS 那道闸不能省——工具老失败或模型绕不出来时,它强制收尾,不然会无限烧钱(A05/A06)。

✓ 里程碑

这一步还跑不完整(run_tool_calls 下一步才写),但代码能读懂:循环、发消息、判断要不要调工具、兜底,四件事齐了。

5第 3 步 · 执行工具,把结果喂回

模型说"调 calculator,参数 expr=1200/100",现在轮到我的代码真正去跑它,再把结果作为一条 tool 消息塞回历史,模型下一轮才能"看"到:

agent.py · 执行工具python
def run_tool_calls(tool_calls, messages):
    for call in tool_calls:
        name = call.function.name
        args = json.loads(call.function.arguments)      # 模型给的参数(JSON 字符串)
        print(f"  · 做:调 {name}({args})")

        try:
            result = REGISTRY[name](**args)             # 按名字找函数、真正执行
        except Exception as e:
            result = f"工具出错:{e}"                     # 出错也告诉模型,让它换招

        print(f"  · 看:{result}")
        messages.append({                                # 结果喂回历史 ← 关键
            "role": "tool",
            "tool_call_id": call.id,                     # 对应上是哪次调用
            "content": str(result),
        })

三个要点:**args 把模型给的参数解包传进函数;REGISTRY[name] 按名字找到真函数(第 1 步那张表);最关键是把结果作为 role:"tool" 消息 append 回去——这就是图 1 里"结果喂回历史",没有它模型下一轮就"看"不到工具结果,循环就断了。tool_call_id 是把结果和刚才那次调用对上号,别漏。

✓ 里程碑

把三步拼起来跑本章开头那个任务,终端里能看到"做/看"一步步打印、最后给出综合答案,agent 就活了。

6第 4 步 · 接上对话、收尾

最后套上 P4 的对话循环,让我能连续给它派活:

agent.py · 主程序python
print("小 Agent 就绪(工具:calculator、get_time)。输入任务:")
while True:
    task = input("任务 › ").strip()
    if task == "exit":
        break
    try:
        print("答 ›", run_agent(task))
    except Exception as e:
        print("[出错了,再试一次]", e)

到这,一个能自己规划、调工具、多步完成任务的小 agent 就做完了。它虽小,但结构和真正的 agent 系统(包括我正在用的 Claude Code)完全一致:循环 + 工具注册 + 结果喂回 + 步数兜底(A05)。

✓ 里程碑 · 完成

给一个要两步的任务(先查时间、再算数),它能自己拆成两次工具调用、最后综合作答——本章开头那段效果达成。

8常见坑

表 1 · 排错速查
症状多半是怎么办
它不调工具、硬答(还算错)工具 description 太模糊把 description 写清楚:什么时候用、参数是什么
报错找不到工具结果 / 消息顺序错漏了把 tool 结果 append 回去,或缺 tool_call_id照第 3 步补全
转圈到 max_steps 也答不完任务太难 / 工具不够 / 模型绕不出加工具、拆小任务;闸本身是对的,别去掉
eval 有风险用户可传恶意表达式(A06 注入)生产改用受限解析(如 ast.literal_eval 或数学库),别裸 eval
一个任务花了好几次调用,有点贵agent 每轮一次模型调用(A06)能写死的用工作流(A04);限 max_steps;简单活别上 agent
