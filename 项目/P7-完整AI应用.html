1成品长什么样

一个网页:访客在浏览器里输入问题,我的后端(拿着密钥、做着限流缓存)去调引擎和模型,把答案返回页面。部署后,它有一个公网网址,谁都能打开用。本地跑起来时,后端终端长这样:

全栈应用的骨架就一条线:前端(浏览器页面)→ 我的后端(密钥、限流、缓存、日志都在这)→ 答案引擎(P5/P6)→ 模型 API。前端只跟后端说话,后端是唯一的关口——密钥永远锁在这里(A07 红线)。

3第 1 步 · 后端关口(密钥 / 限流 / 缓存 / 日志)

先搭那个"唯一关口"。一个 /ask 接口:收前端的问题,做好限流和缓存,调引擎,记日志(A07 的后端代理落地):

backend.py · 关口python
import os, time
from fastapi import FastAPI, Request, HTTPException
from rag import answer                      # ← 复用 P5 的答案引擎(第 2 步细说)

app = FastAPI()
cache, hits = {}, {}                         # 缓存 + 每用户计数(A06 成本/防刷)

@app.post("/ask")
async def ask(req: Request):
    body = await req.json()
    question = body.get("question", "").strip()
    if not question:
        raise HTTPException(400, "问题不能为空")

    user = req.client.host                    # 用访客 IP 粗略区分(生产用登录账号)
    if hits.get(user, 0) >= 50:               # 限流:每人每天 50 次,防刷爆预算
        raise HTTPException(429, "今日次数已用完")
    hits[user] = hits.get(user, 0) + 1

    if question in cache:                      # 缓存:相同问题秒回、不花钱
        return {"answer": cache[question], "cached": True}

    t0 = time.time()
    result = answer(question)                  # ← 调答案引擎(P5 RAG)
    cache[question] = result
    print(f"POST /ask  {question!r}  {time.time()-t0:.2f}s")   # 日志:给监控供数
    return {"answer": result, "cached": False}

这一个函数就把 A07 的四件事全落地了:密钥在引擎里从环境变量读(前端拿不到)、hits 限流、cache 缓存、print 留痕。前端只会 POST 一个问题到 /ask,别的一概不知道——这就是"唯一关口"的意义(也是治理抓手都集中在这里的原因)。

✓ 里程碑

先用假引擎(def answer(q): return "收到:"+q)跑起来,能通就说明后端骨架成立,下一步换真引擎。

4第 2 步 · 接上答案引擎

后端的"大脑"就是我前面做的东西。最省事:把 P5 的 rag.py 放到同目录,它已经有 answer(question) 函数——第 1 步开头那句 from rag import answer 就直接用上了。想让应用更聪明,换成 P6 的 agent:

backend.py · 换引擎(可选)python
# 方案 A(默认):用 P5 的知识库问答,基于你的文档答、带出处
from rag import answer

# 方案 B:用 P6 的 agent,能自己调工具(检索/算数/查时间…)
# from agent import run_agent as answer

# 两者接口一样,都是 answer(question) -> str,后端代码一行都不用改

这就是"模块化"的好处:后端只认 answer(question) -> str 这个约定,底下换 RAG 还是 agent,关口代码一动不动。我前三个项目在这里合流了。

✓ 里程碑

放好 rag.py + docs/,重启后端,用工具发一个真实问题到 /ask,能返回基于我文档的答案,大脑就接通了。

5第 3 步 · 前端页面

一个最简单的网页:一个输入框、一个按钮、一块显示区。点按钮就 fetch 到后端的 /ask,拿回答案显示出来。存成 static/index.html:

static/index.html · 前端html
<!doctype html>
<html lang="zh-CN">
<body style="max-width:640px;margin:40px auto;font-family:sans-serif">
  <h2>我的知识库助手</h2>
  <div id="log"></div>
  <input id="q" style="width:78%" placeholder="问点什么…">
  <button onclick="ask()">问</button>

  <script>
  async function ask() {
    const q = document.getElementById('q').value.trim();
    if (!q) return;
    const log = document.getElementById('log');
    log.innerHTML += '<p><b>问:</b>' + q + '</p>';
    // ← 只跟自己的后端说话,前端不碰密钥(A07)
    const r = await fetch('/ask', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ question: q }),
    });
    const data = await r.json();
    log.innerHTML += '<p><b>答:</b>' + data.answer + '</p>';
  }
  </script>
</body>
</html>

核心就是那个 fetch('/ask', ...):前端把问题 POST 给自己的后端,拿回 JSON 里的 answer 显示。注意它从头到尾没碰密钥——密钥在后端,浏览器里看不到(A07 红线)。让后端顺便托管这个页面,加一行:

backend.py · 托管前端(加在末尾)python
from fastapi.staticfiles import StaticFiles
app.mount("/", StaticFiles(directory="static", html=True), name="static")   # 访问 / 就给 index.html
✓ 里程碑

本地跑起来(下一节),浏览器打开能看到页面、输入问题能显示答案,前后端就打通了。
